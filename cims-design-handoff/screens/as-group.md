## G1 · 시스템/서버 구성

Info Alert:
```

표시값 기준은 ACTIVE 노드 Control-01 입니다. 개별 서버만 바꾸려면 좌측 트리에서 해당 서버를 선택하세요.
```

**그룹 설정** — 그룹 이름* · auth_pass*(VRRP 인증) · note
**절체 조건 (A/S 전용)** — 요약 `감시주기 1s · 장애판정 2회 · 자동 복귀 없음`, 기본 접힘. 9필드:
감시 주기(초) · 점검 주기(초) · 제한 시간(초) · 장애 판정(회) · 복귀 판정(회) · 승격 유예(초) · 재기동 임계(회) · 판정 윈도우(초) · 권한 복귀 정책 + 서비스 NIC 링크 감시(스위치)

**멤버 (2)** — 부제 `추가·삭제는 좌측 트리에서 · MASTER 는 하나만 지정`
| 이름 | 역할 | MASTER | 상태 | 접속 | IP | Agent |
- MASTER 는 라디오, 역할은 M/B 배지
- 하단 `실측 새로고침`

**VIP Bindings (n)** — 힌트 `네트워크·마스크는 멤버의 service IP 에서 자동 매핑 — host 옥텟만 입력`
| 용도 | VIP (네트워크 + HOST) | MASK | 멤버 IFACE | 보유 | 액션 |
- `보유` = 현재 VIP 를 들고 있는 노드 (StatusDot + 노드명)
- 액션 줄: `수동 입력`(토글) · `+ VIP 추가` · `↻ 재적용`
- 0건이면 ES-1

**마운트 (그룹 공통)** — 멤버별 상태 컬럼. 미적용이 있으면 ES-5

저장바: `[변경 n건 · 전 멤버 적용] 그룹 설정 · 절체 조건 · 멤버 · VIP 를 한 번에 저장 — keepalived 재생성`

> **미결**: 웹은 섹션마다 `▶ 적용` 버튼이 따로 있습니다(4개). 시안은 하단 통합 저장바 1개입니다. 어느 쪽으로 갈지 정해야 합니다.

## G3-1/3/5 · 패키지 설정 · 공통 설정

상단: `모듈 운영 명세 (감시 · 절체 모드)` 접힘 → 모듈 칩(모듈 · 버전 · `⬤ 동기화`) → `SyncStatusRow` → 세그먼트 `공통 설정 (9) | 멤버 비교`

**공통 설정 9필드 · 4섹션**
1. `OAM 서버 / 포트` — OAM bind 포트 (실제 listen) 🔁
2. `서비스 로그` — 서비스 로그 루트 🔁 · 알람 스트림 보존일 🔁 · 이벤트 스트림 보존일 🔁
3. `관리 store` — 런타임 store 🔁 · 런타임 마운트 지점 🔁 · 패키지 저장소 🔁
   + 경고문 2줄 + **`→ <경로> 으로 이관` 버튼**
   ```
   경로를 바꾸려면 [이관] 을 쓰세요 — 저장은 경로만 바꾸고 데이터를 옮기지 않습니다.
   새 경로에 빈 store 가 생기거나, 마운트가 없으면 OAM 이 기동을 거부합니다.
   이관은 정지 → 복사 → 기동을 한 번에 처리합니다.
   이관은 HA 그룹 멤버에서만 실행할 수 있습니다.
   ```
4. `관리망 · agent 접속` — Agent→OAM URL (신규 설치용) 🔁 · 관리망 CIDR ⚡

저장바: `[변경 n건] 저장하면 멤버 2대의 <모듈> 설정이 재생성되어 적용됩니다 · 재기동 필요 항목 포함`

## G4 · 패키지 제어

Warning Alert (VIP 가 1건 이상일 때만):
```
동시 정지·재시작은 VIP 서비스 중단을 유발합니다
<그룹> 은 VRRP vrid n 로 VIP x.x.x.x 을 서비스합니다. 멤버 2대를 동시에 내리면 대체 경로가 없습니다.
```

`그룹 일괄 제어`
```
[▶ 일괄 시작] [⟳ 일괄 재시작] [■ 일괄 중지]  │  [⇄ 수동 절체 (현재 <노드>)]
```
- 구분선으로 프로세스 제어와 HA 절체를 갈라놓습니다
- `일괄 중지` 만 destructive

`멤버별 프로세스 제어` — 서버명 아래 `점검` `복귀` (outline), 모듈별 시작/재시작/정지
- uptime · PID · 메모리는 멤버 상세에서. 그룹 화면은 **멤버 간 상태 일치 여부**에 집중
