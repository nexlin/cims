## 3. 회귀 FAIL 근본 원인 (중요)

CSP 로그 발췌 (`dist/csp/log/csp_20260422_2.log`):

```
[20:38:47] ServiceMap: sync complete, 0 services       ← access_services.jsonl 빈 파일
[20:38:47] LocalNodeMap: sync complete, 0 nodes        ← local_nodes.jsonl 부재
[20:38:47] RouteMap: sync complete, 0 routes
[20:38:47] RoutingPolicyEngine: sync complete, 0 policies
[20:38:47] AclPolicyEngine: sync complete, 0 policies

[20:38:51] Auth reject: user=+821357007001 service_id=1
           imsi='450033100000001' — 데이터 불완전
```

### 3.1 원인 체인

1. **v3 재구조화 후 `access_services.jsonl` 파일이 존재하지 않음**
   - 구 `services.jsonl` → 새 `access_services.jsonl` 마이그레이션이 실 환경에 적용되지 않음.
   - 문서 `sip_service_model.md §7` 의 수동 변환 또는 `tools/migrate_csp_sip_config_v3.py` 실행 전 상태.
2. **CspServiceMap.GetById(1) → 빈 ServiceInfo 반환** (0 services 로드됨)
3. **CscfModule.CheckAuthorization**: `svc.id > 0 && !imsi.empty()` 조건 실패 → "데이터 불완전" reject

### 3.2 더 깊은 설계 gap

- v3 `access_services.jsonl.id` = UUID 문자열 → `CspUuidToIntId(uuid)` 해시로 int 변환
- DB `voip_subscriptions.service_id` = INT (레거시 sip_service.id 참조값)
- **두 int 값은 서로 다른 네임스페이스** — 해시 충돌로 우연히 같아질 가능성 ≈ 0

즉 **단순히 access_services.jsonl 파일을 채우는 것만으로는 부족**. 다음 두 옵션 중 하나로 subscriptions 와 v3 서비스 간 매핑 체계를 정해야 함:

| 옵션 | 방식 | 장단점 |
|---|---|---|
| A | `voip_subscriptions.service_id INT` → `service_ref VARCHAR(64)` (name 참조) + CspUser/DbManager 수정 | 깔끔. 스키마 migration + CspServiceMap 조회 API 추가 필요 |
| B | `access_services.jsonl` 에 `legacy_service_id INT` 필드 추가 → ServiceMap 이 해시 대신 이 값으로 매칭 | 최소 변경. 운영자가 수동으로 int id 관리 (오류 위험) |

**권장: A**. v3 의 방향성 (name 기반 참조) 과 일치.
