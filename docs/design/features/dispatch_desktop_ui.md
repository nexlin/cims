# 관제조작반 앱 UI — Windows 데스크톱(WPF) 화면 설계

> 관제 센터 기능([dispatch_center.md](dispatch_center.md))과 보조 서비스([volte_supplementary_services.md](volte_supplementary_services.md))의
> **관제사 화면**을 정의한다. 앱은 `windows/dispatch-desktop`(WPF, MVVM, `net10.0-windows`)이며 SDK 는
> [ue_sdk.md](ue_sdk.md) 의 .NET 파사드 `CimsUe.dll`(→ C API `cimsue_c.h` → `libcimsue`) 만 참조한다. 요구↔코어 API 대응표는
> ue_sdk.md §7 이 정본이고, 이 문서는 그 위의 **화면·조작·표시 규약**을 정한다. Android 태블릿 관제 앱은 같은 패널을
> 다른 밀도로 배치한다(§12).

## 1. 범위와 결론

- **모드마다 한 화면.** 관제 화면은 탭 줄의 **[무전|통화]** 세그먼트로 둘을 가르고, 한 모드 안의 일은 넘기지 않고 한 화면에 편다.
  [무전] = 2×2 — 위 줄 **내 채널 | 타 채널**, 아래 줄 **메시지 | 이벤트**. [통화] = **통화 | 기록**(통화 + 문자를 상대별로). 낱말·조작 문법은
  Android 태블릿([android_dispatch_tablet.md](android_dispatch_tablet.md) §6.3)과 같고, 데스크톱은 면을 넘기지 않고 폭을 쓴다(§12).
- **왼쪽 칸 1040 = 지금 하는 일, 오른쪽 칸 = 둘러보는 것.** 두 모드 모두 왼쪽 칸(내 채널 / 통화)은 폭과 자리가 고정이다 — 말하려던 카드, 받으려던 호가
  움직이지 않는다. 한 대상을 자세히 보거나 사람을 찾는 일은 **오른쪽 패널 440** 하나가 받고(채널 상세·사용자·새 PTT 그룹·이벤트 상세·주소록 — §3.6),
  패널은 본문 위에 겹쳐 오른쪽 끝에서 밀려 들어온다(본문 칸 배치는 그대로).
- **말하는 곳과 듣는 곳을 칸으로 나눈다.** 내 채널 = 멤버 그룹 + **내가 건** 개별·애드혹 통화 — 필터·검색 없이 **항상 전부** 보이고 발언 대상 ✓ 는 이 칸에만
  있다. 타 채널 = 청취 범위 그룹(타인 간 개별·애드혹 세션의 자리) — 필터·검색은 여기만, 조작은 [청취] 하나다.
- **발언 바는 모든 화면 하단 80 에 하나다.** PTT + 발언 대상 칩(상태 · ×) + [모두 해제]. 카드의 ✓ 가 발언 대상이고 여러 개 고르면 한 번의 PTT 로 대상 전부에
  floor 를 요청한다(동시 발언, §4.1). **고른 카드(채널 상세가 보는 채널) ≠ 발언 대상(말하는 채널)** — 카드를 누르면 채널 상세가 열리고 «메시지» 가 그 채널
  대화로 따라간다.
- **카드 = 네 줄 · 조작 하나.** «핀 번호. 이름» · 발언자 · 접속자 · 참가·경과, 조작은 ✓(발언 대상) / 음소거(전이중 개별 통화) / [참여][긴급](미참여 멤버 그룹)
  중 하나. 나머지 조작(나가기·긴급 해제·일제 통화·출력·편집)은 채널 상세에 있다.
- **놓치면 안 되는 것은 배너, 명령 실패는 토스트.** 긴급·임박·경보 = 꽉 찬 면(닫기 없음 — 조건이 내려가면 스스로 빠진다), 착신 = 옅은 면 [응답][거절],
  서버 인증서·자격 경고 = 한 줄. 배너는 상단 바 아래라 어느 화면에서나 보이고, 토스트는 본문 우하단.
- **감청·청취는 축이 아니라 상태다.** VoLTE 감청은 «진행 중» 행이 그 자리에서 펼쳐지고(소스 귀속 두 줄·은닉/투명·출력), PTT 청취는 타 채널 행의 [청취 중] +
  채널 상세(청취 전용·음량)다. 켜는 자리가 곧 끄는 자리이고, 감청 창(별창)은 [창으로] 를 눌렀을 때만 뜬다(§5).
- **레일 다섯 — [관제 F1] · [이력 F2] · [PTT 그룹 F3] · [관리 F4] · 바닥 [설정].** 전부 한 번에 누른다(메뉴를 거치지 않는다). [관제] 가 위의 두 모드 화면이고
  [이력]·[PTT 그룹]·[관리] 는 같은 창의 화면 전환, [설정] 은 설정 창이다(§3.4).
  발언 바·배너·토스트는 어느 화면에서나 같다. 관제 요약 띠는 화면 별창에만 붙는다(§3.5).
- **고정 배치 + 칸 경계 끌기.** 도킹·패널 별창·배치 프리셋은 두지 않는다. 끌 수 있는 경계는 셋 — [무전] 위/아래 줄 · 대화 목록 폭 · 기록 목록 폭 —
  이고 `layout.json` 에 기억한다(§3.3).
- **화면 한 장, 스크롤 없음.** 설계 캔버스 1920×1080, 목록이 넘치면 그 칸 안에서만 스크롤한다. 창이 좁아 오른쪽 칸이 360 보다 작아질 때만 왼쪽 칸을
  줄인다(640 까지).
- **영상 = MCVideo 영상 채널** — MCPTT 와 나란한 서비스라(TS 23.280 §3) 같은 그룹 카드에서 음성 호와 따로 든다. «영상 참여» 단계가 없다 — 앱이 내 채널의 영상 채널에
  영상 호도 함께 합류한다(D10). 카드는 «영상 n»(보내는 중 수) 태그만, 골라 보기는 채널 상세 «영상» 절 [보기]/[바꿔 보기]/[그만 보기](한 번에 하나), 새 송출은 «새 영상» 배너(§10).
- **테마 기본 = 밝게** — 무채 표면 + 브랜드 남색(`#4F46E5` — 채운 주 행동·선택) + 상태색(연한 면·채움). 어둡게는 설정에서 고른다(`UiVersion` 없는 옛 설정을 처음
  읽을 때 한 번 밝게로 되돌린다). 두 테마는 같은 토큰 키를 쓰고 창 제목 표시줄도 테마를 따른다(§3.2 «색»).

### 3.3 배치 — 고정 + 칸 경계 끌기

- **고정 배치다.** 도킹·패널 별창·배치 프리셋은 두지 않는다 — 칸을 옮기고 떼는 자유보다 «모드마다 한 화면» 의 한눈 파악이 관제에 맞다(§1).
- **끌 수 있는 경계는 셋** — [무전] 위/아래 줄(기본 292, 200~520) · «메시지» 대화 목록 폭(기본 300, 220~480) · «기록» 상대 목록 폭(기본 300, 220~480).
  끈 값은 놓을 때 `%APPDATA%\CIMS\dispatch-desktop\layout.json` 의 `Seams` 에 저장한다. 왼쪽 칸 1040 은 끌지 않는다.
- `layout.json` = 판(4) · 주 창 위치·크기·최대화 · 감청 창 위치 · `Seams`. 판 3(도킹 프리셋 파일)을 읽으면 그 현재 프리셋의 창·감청 창 위치만 옮겨 판 4 로 쓴다.
- 창이 1920×1080 보다 작으면 재배열하지 않는다 — 오른쪽 칸이 360 에 못 미칠 때만 왼쪽 칸을 줄인다(640 까지). 오른쪽 칸이 좁으면([무전] 560 · [통화] 640 미만 —
  오른쪽 패널은 겹치므로 셈에 들지 않는다, §3.6) 좁은 배치다 — 타 채널 1열 · 이벤트 채널 열 접기 · 동시 청취·[이력에서 보기]·CSV 숨김 / «기록» 목록만(제목·CSV 숨김, 머리·칩 여백을 줄이고 [대표번호] = [대표]). [통화] 머리 줄의 번호칸은 300 에서 150 까지 줄어 [발신]·[키패드]·[픽업] 이 잘리지 않는다. 카드·타 채널 격자는
  칸 폭으로 열 수를 정한다(카드 최소 230 — 4열까지, 타 채널 최소 250 — 3열까지). 높이도 같다 — 끌어 둔 [무전] 위 줄이
  창보다 커 아래 줄(메시지·이벤트)이 220 밑으로 밀리면 보이는 높이만 줄인다(저장값은 그대로, 창을 키우면 돌아온다). 작은 화면은 OS 배율이 fit 역할.

| 레일 | 키 | 화면 | 활성 조건 |

| **관제** | F1 | §3.1 [무전]·[통화] 두 화면 | 항상 |

| **설정**(레일 바닥) | — | 설정 창(모달) | 항상 |

- **같은 창의 화면 전환.** 관제 두 화면은 항상 마운트돼 있고 레일 화면은 그 자리에 겹친다 — 가시성만 바뀐다. 상단 바·배너·발언 바·토스트는 공통이라
  어느 화면에서나 보이고, PTT 핫키도 어디서나 발언 대상에 동작한다. 감청 창(§5)은 별창이라 영향이 없다. 탭 줄은 관제 화면에만 있다.
- **화면 VM 은 앱 수명 동안 하나, 서버 자료는 로그인 뒤 처음 레일 화면을 열 때 한 번 적재**(이후는 화면 안 [새로고침]·저장 후 재조회). 착신 응답으로 관제에
  다녀와도 편집 중이던 폼은 그대로다. 저장하지 않은 폼은 레일 [관리] 의 점 배지와 화면 머리의 "저장하지 않은 변경" 배지로만 알리고 **전환을 막지 않는다**.
- **자동 복귀 규칙.** 세션을 **만드는** 조작 — 발신·응답·당겨받기·개별·애드혹 통화(배너 [응답]·전역 핫키 응답 포함) — 은 **그 호의 모드**(전화 = [통화],
  PTT = [무전])로 **호마다 한 번** 돌아온다(보류·전달·종료 버튼이 거기 있다 — 통화 중에 관제사가 모드를 바꿔도 다음 상태 변화가 되돌리지 않는다).
  착신(링잉)·멤버 채널 합류·감청/청취는 배너·행만 바꾸고 화면을 옮기지 않는다. 배너 [채널로 이동]·«이벤트» [채널로]·`Ctrl+K` [채널로] 는 관제 [무전] + 그 채널
  상세(합류 없음). 로그아웃·재로그인은 관제 [무전].
- **↗ 별창으로.** 레일 화면([이력]·[PTT 그룹]·[관리])은 머리의 [↗ 별창으로]로 별창(`ScreenWindow`, 1180×760)에 떼어 두 번째 모니터에 둔다. 별창에는 관제 요약
  띠(§3.5)가 붙는다. 떼어낸 동안 주 창 쪽은 자리표시자("이 화면은 별창에 열려 있습니다 · [별창 앞으로]")만 보이고(같은 VM 을 두 뷰가 동시에 붙지 않게 — 녹취
  재생·비밀번호 상자), 별창을 닫으면 주 창 화면으로 돌아온다. 로그아웃 시 별창은 닫힌다. **앱 포커스 핫키(§8)는 별창에서도 주 창과 같은 규칙**으로 동작한다
  (별창이 주 창의 키 처리로 넘긴다) — 별창에서 F1~F4 를 누르면 대상 화면이 별창이면 그 별창을, 아니면 주 창을 앞으로 가져온다.
- **«이벤트»·«기록» → 이력.** [이력에서 보기]는 종류(PTT/통화)를 맞춰 [이력]으로 넘어간다 — 오늘·진행 중은 관제 두 화면이 정본, 끝난 세션의 날짜 조회는 이력.

### 3.5 관제 요약 띠 (화면 별창)

레일 화면을 **별창**으로 뗐을 때 그 창 상단 32px 에 상시 — 주 창은 발언 바가 모든 화면에 있어 띠를 두지 않는다. 다른 VM 의 투영이라 상태를 갖지 않고
1초 틱·선택 변경 때 갱신한다.

```
│ 발언 대상 3 순찰1·상황실·교통1 ⚠긴급 │ 발언 김순경 ▬▬▬ 00:08  [PTT] │ 대표번호 대기열 1 │ 내 통화 통화 1 · 보류 1 │ 감청 1 │            [관제로 F1] │
```

### 3.6 오른쪽 패널 (440)

한 대상을 자세히 보거나 목록에서 사람을 찾는 자리는 하나다. 패널은 **본문 위에 겹친다** — 오른쪽 끝에서 왼쪽으로 밀려 들어오고(220 ms, 감속) 닫으면
오른쪽으로 밀려 나간다(180 ms, 가속). 본문(두 모드의 칸)은 폭·배치를 바꾸지 않고 오른쪽 440 이 패널 아래에 가려진다. 같은 패널 안에서 내용만 바뀌면(다른 대상 =
교체) 움직이지 않는다. 시스템 설정 «애니메이션 효과» 를 끈 사용자에게는 곧바로 열고 닫는다(`SystemParameters.ClientAreaAnimation`). 토스트는 패널이 열린 동안
패널 왼쪽에 선다. 머리 56 = [←](패널 안에서 들어간 것만) · 종류 라벨 · 제목(19 굵게) · 핀(채널 상세·사용자·주소록) · ×.

- **일제 통화**(TS 24.379 §4.12 — 그룹 종류가 아니라 호 속성, [mcptt_broadcast_group_call.md](mcptt_broadcast_group_call.md) §4.4 U6): 관제사 개시는 미참여 멤버 그룹의
  채널 상세 [일제 통화] — 멤버 편성 그룹에 진행 중 세션이 없을 때만 활성(진행 중이면 서버가 합류로만 받는다 — 그 문서 §3.2. chat 그룹은 서버가 broadcast-ind 를
  무시해 비활성 — TS 24.379 §6.2.8.2 는 broadcast-ind 를 prearranged 그룹 호에 싣는다. 그룹 종류는 관리 목록 `sessionType`, 관리 범위가 없어 모르면 누를 때 GMS 그룹
  문서의 `on-network-invite-members`(TS 24.481 §7.2.2 a)로 확인). 진행 중인 호는 일제 통화로 바꿀 수 없다(TS 24.379 §10.1.1.3.1.1 15) — 진행 중 호의 INVITE 는 합류).
  **[일제 통화] 는 한 버튼이다 — 누르고 있는 동안 개시하고 말하며, 놓으면 끝난다**(잠금 발언 설정이면 누를 때마다 켜고 끈다, 켜진 동안 "일제 통화 중" 남색).
  개시 INVITE 가 암묵적 발언 요청이라(`GroupCallOptions{broadcast, implicitFloorRequest}` — offer `mc_implicit_request;mc_granted`, TS 24.380 §14.2.4·§14.2.5)
  PTT 를 따로 누르지 않는다. 개시 카드는 단일 발언 대상이 된다(내가 건 호 우선과 같은 규칙). 놓으면 호 성립 전 = 호 취소(CANCEL — 말하지 않은 일제 통화는
  열지 않는다), 성립 뒤 = Floor Release → 서버의 B-bit Floor Idle 에 코어가 호를 해제(TS 24.380 §6.2.4.6.4 — 승인 전에 놓아도 늦은 Granted 는 무시, §6.2.4.6.8).
  그룹 종류 조회(GMS) 중에 놓으면 개시 직후 끝낸다. 버튼(`HoldButton`)은 포인터 캡처·터치로 뗌을 놓치지 않고, 개시 뒤에도 `IsBroadcastHeld` 로 활성을 유지한다.
  **일제 통화용 그룹은 그룹 이름으로 알린다** — 그룹 문서(TS 24.481)에 일제 통화 표시 요소가 없어 멤버 단말에 그룹 성격을 알리는 규격 수단은 `<display-name>` 뿐이다
  (예: "전원 일제"). 통화가 오면 단말이 착신 `broadcast-ind`·floor B-bit 로 일제 통화임을 표시한다. 일제 통화 카드는 라벨 "일제" · 2줄 "일제 통화 · 발언을 놓으면 종료 /
  수신 전용". 판정은 서버가 알린 값 — 착신 mcptt-info `broadcast-ind` 또는 floor 메시지 B-bit(진행 중 일제 통화에 늦게 합류한 leg 은 B-bit 로만 안다). 수신 멤버(Taken
  Permission 0 — Floor Idle 에는 Permission 필드가 없다)는 ✓ 불가(점선). 서버가 일반 통화로 연 개시(첫 서버 floor 메시지 — Deny 포함 — 의 Floor Indicator 에
  B-bit 없음)는 경고 토스트 — 200 OK 의 승인 표시(`mc_granted`, 서버 floor 메시지가 아니라 `RawType` -1)는 판정에 쓰지 않는다. «이벤트» 에 개시·수신·종료 줄.

[음소거](전이중) · [종료] / 애드혹 = [✓ 발언 대상] · [종료] · 공통 ⋮ = [편집 — PTT 그룹 화면] · [삭제…](내 소유·관리 범위만 — GMS XCAP DELETE 확인 후).
로스터 = [접속 n | 편성 m](§3.6) — 사람 줄 [개별] = 반이중 개별 통화, [SDS] = 1:1 무전 메시지.

**사용자 패널에서 여는 개별·애드혹**(§3.6): 사람을 골라(☐, 최소 1) **[애드혹 열기 · 지금 한 번]** = `joinGroupCall(acc_ptt, "adhoc-<내 PTT 번호>-<epoch초>",
{members: tel: URI[], emergency})` → 카드가 생기고 단일 발언 대상이 된다. **[일제 통화]** = 고른 사람들에게 애드혹 일제 통화(TS 24.379 §17.2.2.1.1 9)) — 그룹 [일제 통화] 와
같은 한 버튼이고 누르는 동안은 고른 사람이 잠긴다. 서버가 ad hoc 의 broadcast-ind 를 받지 않으면 일반 애드혹 그룹 통화로 열리고 «일제 통화로 열리지 않았습니다» 경고.
**개별 통화**는 줄 ⋮(사람 메뉴) [개별 통화] = 반이중 `startPrivateCall(acc_ptt, peer, {fullDuplex:false})`(채널 상세 로스터 [개별]도 같다). [그룹으로 저장 ›] = 패널
«새 PTT 그룹»(멤버 = 고른 사람). 애드혹 그룹 id 는 앱이 만든다(mcptt_emergency_modes.md §6 규약; `adhoc-`·`priv-` 는 편성 그룹 예약어) — 채널 영속·affiliation·
로스터 구독 대상이 아니다. 자격 선차단: CMS user-profile(`allow_adhoc_call`·`allow_emergency_private_call`·`PrivateCall/EmergencyCall/MCPTTPrivateRecipient`) 에 없으면
해당 조작 비활성 + 툴팁. 긴급 개별 통화 `UsePreConfigured` 면 대상을 사전 지정 수신자로 잠금(mcptt_emergency_modes.md §7). 파싱 API 는 §13.

**발언 대상 · 발언 바**(§3.2):
- **발언 대상** = 카드 **✓**. 참여 중인 멤버 그룹·애드혹 그룹·개별 통화(반이중)만 켤 수 있고, 미참여·전이중 개별 통화에는 ✓ 가 없다(전이중은 항상 열린 마이크 —
  [음소거]). 대상이 없으면 PTT 는 흐리고 발언 바가 "채널 카드의 ✓ 를 누르세요".
- **PTT**: 누르는 동안 대상 전부에 `floorRequest`, 떼면 `floorRelease`. **잠금 발언** 토글(설정, 기본 꺼짐 — 클릭으로 누름 유지, 다시 클릭 또는 요청한 대상이 **전부**
  끝나면(`TalkLimit`·`Revoked`·`Denied`) 해제 — 한 채널의 회수가 나머지 발언을 풀지 않는다; 풋스위치·긴 공지용).
- **대상 칩** = "이름 · 상태": 요청 전 "대기" · 요청 · 승인(녹색 채움) · 대기 n번째(주황 테두리) · 거부·사유(빨강, `causeText`). 발언 중 남은 시간은 승인된 대상 중 **최소값**을
  발언 바 오른쪽 게이지에. 칩을 누르면 그 채널 상세, × = ✓ 해제.
- **발언 세트**(선택, **미구현** — §13): ✓ 조합을 이름으로 저장(예: "야간" = 순찰1+순찰2) — `Ctrl+Shift+F1..F4`. `layout.json` 옆 `talksets.json`.
- **핫키**: `Ctrl+n` = **발언 대상을 카드 n 하나로**(단일 모드 복귀) + «메시지» 가 그 채널로(채널 상세는 열지 않는다), `Ctrl+Shift+n` = 카드 n ✓ 토글(다중 추가).
  어느 화면에서나 같다.
- **동시 발언 = 단말 팬아웃**: 3GPP 에 UE 의 다중 그룹 동시 발언 절차가 없어 단말이 편다 — 대상 세션마다 `floorRequest`, 코어가 **승인된 세션마다** 같은 캡처를 결선한다
  (세션별 floor participant·`micOpen` → `wireMedia`, 단일 발언 호 가정 없음 — ue_sdk.md §6.3). 부분 상태(일부 승인/대기/거부)는 세션별 floor 이벤트 그대로. 서버 변경 없음,
  대상 수 상한 없음. 발언 세트·핫키 외 별도 코어 API 는 두지 않는다(대상 집합은 앱의 화면 상태).
- **요청한 floor 만 해제한다**(불변): 앱은 floor 를 요청해 둔 세션 집합을 발언 대상(✓)과 **따로** 든다. 누른 채 대상이 바뀌면(칩 ×·`Ctrl+n`·내가 건 호 우선·세션 종료)
  빠진 세션에 곧바로 `floorRelease` — 그러지 않으면 화면은 새 대상을 가리키는데 마이크는 옛 채널로 계속 나간다. 뗌도 «현재 대상» 이 아니라 요청한 집합 전부를 상태와 무관하게
  놓는다(요청 직후 Granted 전에 떼도 반드시 놓게 — 코어 release 는 유휴에서 no-op). 요청·해제 직후 세션 floor 상태를 코어에서 다시 읽어 투영을 맞춘다(요청은 이벤트 없이 Requesting).
- **내가 건 호 우선**: 내가 건 애드혹 그룹 통화·반이중 개별 통화·일제 통화는 생기면 곧 단일 발언 대상이 된다(발신자가 곧 말하려는 채널). 카드를 고르지는 않는다
  (고르기 = 채널 상세).

**사람 메뉴**(채널 상세 로스터 이름·사용자 ⋮·주소록 줄·«관제 그룹원» 칸 오른쪽 클릭·«내 통화» 상대 이름·«기록» ⋮): 머리 = 이름 · PTT 번호 · 내선, 항목 =
[통화 <내선>][문자 <내선>] / [개별 통화 <PTT>][무전 메시지 <PTT>][애드혹에 추가] / [기록 보기]([통화] «기록» 의 그 사람 한 줄기). 회선이 없는 항목은 비활성.
**통합 검색** `Ctrl+K`(상단 바 검색 칸) = 같은 행동을 이름 하나로(사람 행 = 소속·PTT 상태·내선 상태 + [통화][문자][개별 통화][무전 메시지][애드혹에 추가], 그룹 행 =
[채널로][멤버 추가]; ↑↓ 이동 · Enter 첫 행동). 주소록 소스는 서버 전화번호부(`service=volte` = 전화 가족 축(이동 volte+유선 voip 서버 합산)·`ptt`, §13) — PTT 와
일반통화가 같은 사람을 두 번 찾지 않게.

### 4.2 [무전] 타 채널 (위 줄 오른쪽)

**소스**: 프로비저닝 `dispatch.pttTargets[]`(청취 범위 그룹 — conference 구독 → 진행/참가자 수/발언자) · **타인 간 개별·애드혹 통화 세션**(관제 범위 안 —
`dispatch.members[].pttId` dialog 구독, 서버 계약 [dispatch_center.md §5.6a](dispatch_center.md); 앱 구현은 §13). 내 멤버 그룹과 내가 건 세션은 여기 없다(내 채널).
관리 범위·내 소유로만 보이는 그룹(세션 상태 없음)은 여기 두지 않는다 — 레일 [PTT 그룹] 이 맡는다(§4.7).

- **머리**: "타 채널 [청취 가능] n" · 동시 청취 n/상한(설정 — 기본 4) · 🔍(검색 칸 열기 — 그룹명·id) · 필터 칩 **[전체|활성|긴급|청취 중]** — 필터·검색은 **이 칸에만** 걸린다.
- **행**(56, 3열 — 칸이 좁으면 1열): 점(청취 중 먹 · 진행 흐린 회색 · 긴급 빨강) · 이름 · 한 줄(`발언 <이름>`(+ 긴급 개시 시각) / `세션 진행 중 · 참가 n` /
  `마지막 세션 hh:mm · 길이` / `대기`) · **[청취]**(외곽선) / **[청취 중]**(먹 채움 — 누르면 청취 종료). 세션 없는 그룹은 [청취] 비활성. 정렬 = 긴급 › 청취 중 › 진행 › 대기.
  행을 누르면 채널 상세(고른 행 = 남색 테두리).
- **[청취]** = `joinGroupCall(listenOnly)`(recvonly — TS 24.379 §10.1.1, dispatch_center.md §5.6) → 행이 [청취 중], 채널 상세에 "청취 전용 — 발언 요청 불가" + **음량**
  (`SetRxLevel`, 0~200%) + [청취 중지] · [창으로 ↗](PTT 청취 창, §5) · 출력 [헤드셋/스피커]. 멤버가 아니면 ✓·PTT 는 없다. 타인 개별/애드혹 통화 → [청취](서버 인가 시).
- **상태 소스**: RFC 4575 conference 구독(`subscribeConference` → `onRoster`) — 청취 범위 그룹은 서버 인가(dispatch_center.md §5.6, 403 + Warning 138 은 `Area.PttListen`
  문구로 흡수). 발언자는 청취 중인 세션만(floor 이벤트) — 청취하지 않는 세션은 "세션 진행 중 · 참가 n" 까지. 참여/청취하지 않는 그룹의 경과는 로스터로 세션을 관측한 시점부터.
- 채널 상세 ⋮ [편집]·[삭제] 는 관리 범위·내 소유 그룹일 때만(관리 목록 `canManage`).
- 구독 슬롯(`PJSUA_CIMS_MAX_SUB` 256, dialog·conference·xcap-diff 공용 — ue_sdk.md §3)은 청취 범위가 넓은 조직에서 예산을 본다.

### 4.3 [통화] 통화 (왼쪽 칸)

위에서 아래로 **머리 줄 → 대표번호 대기열 → 내 통화 → 진행 중 · 관제 그룹 → 관제 그룹원**.

**머리 줄**(56): `통화 [번호 · 내선 · 이름 — 숫자를 치면 여기로] [발신] [키패드] [픽업 (가장 오래 울린 호)]`. 번호칸 Enter = `dial(acc_volte, target)`(내선·번호·이름
자동완성 제안, `sip:` URI 허용), [픽업] = `pickup(code)`(피처코드 = 접속서비스 `pickup_feature_code`, 기본 `**`). **[키패드]** = 누를 때만 뜨는 팝오버(292 — 화면 +
3×4 키 + [←][발신], Esc 로 닫기): 번호칸에 채우고, **통화 중이고 번호칸이 비면 DTMF** 로 보낸다(보낸 자릿수를 화면에).

**대표번호 대기열** — 대표번호 AoR dialog(dispatch_center.md §4.5): 발신자 · 링 경과 · "울림 <그룹원 라벨>"(포크 대기 leg) · [당겨받기]=`pickup(code, pilotId)`.
자기 단말도 울리면 [응답](**이 발신자의 내 착신 leg 만**). 응답되면 "응답: 1004 정경장" 3초 후 제거, 그 호의 leg 가 전부 끝나기 전까지 NOTIFY 재수신으로 되살리지 않는다.
**항목 = 발신자 기준 한 호**(서버가 포크 집합당 dialog 하나 — id=A-leg Call-ID; 앱 병합은 구 서버 호환으로 유지). 초기 full 스냅샷에 진행 중 대표번호 호가 실려 재로그인
즉시 보인다. sequential 모드는 한 명만 울린다. 빈 상태: "대기 호 없음". 전화 그룹이 없으면(`HasDesk` 거짓) 대기열·진행 중·그룹원 칸을 접는다(§6).

**내 통화** — `calls()` 중 VoLTE 통화(`!isMcptt && !listenOnly`) 카드:
- 펼친 카드(활성·착신·발신·상담): 상대(누르면 사람 메뉴) · **착신 경로 라벨**(`calledParty`=pilot → "대표 7000 착신" / "직접") · 음소거 라벨 · 출력 아이콘 · 상태·경과 ·
  [응답][거절](착신 — 486) / [보류][음소거|음소거 해제][DTMF][전달] + [전달 완결][취소](상담) · [종료]. [DTMF] = 카드 옆 3×4 팝오버, [전달] = 대상 입력 + 그룹원 알약 팝오버
  ([상담 전달][전달]). 활성 = 녹색 테두리, 착신 = 주황 면.
- **보류 카드는 한 줄로 접는다** — 상대 · 보류 경과 · [보류 해제][종료].
- blind 전달: `transfer` — "전달 중 → 1003", 서버 BYE 로 카드 소멸·토스트. 실패면 원 통화 유지.
- attended: [상담 전달] → 원 통화 자동 보류 + `dial` 상담 카드(라벨 "상담") → [전달 완결]=`transferAttended(원, 상담)` / [취소].
- 활성 통화 중 새 착신 응답 → 기존 통화 자동 보류(설정: 자동 보류/거절).

**진행 중 · 관제 그룹** — 감시 대상 dialog 를 **세션 행**으로 결합: `A ↔ B`(내선은 이름 병기) · [대표](대표번호 경로 — 대표번호 AoR dialog 와 발신자 상관) · 상태·경과 ·
조작 하나 — 링잉 → [지정 픽업], 통화(confirmed) & 범위 안 → **[청취]**(`join(dlg)`), early/범위 밖·자기 통화 → 없음(툴팁). 정렬 = 청취 중 › 링잉 › 진행 시작 역순.
- **감청 = 행 확장**: 청취 중인 행은 그 자리에서 펼쳐진다(연한 보라) — 은닉/투명 라벨(`listenVisibility`) · caller / callee 두 줄(RFC 5576 `label` — 이름 + 레벨 막대,
  `MediaSource.level/active`) · 출력 · 음량 · [창으로 ↗](감청 창, §5). 행 머리는 "청취 중" + [청취 종료](`hangup`).
- **결합 규칙**: 감시 대상 두 내선이 서로 통화하면 dialog 가 두 개(각 leg — Call-ID 가 다름) 온다. `remoteIdentity` 가 서로를 가리키고 전이 시각이 근접하면 한 행(어느 leg 로도
  Join 가능 — dispatch_center.md §5.3). 한쪽만 감시 대상이면 그 leg 하나.

**관제 그룹원** — BLF 4열 칸(40): 점(대기 흐림 · 링잉 주황 · 통화 녹색 · 청취 중 보라) · 내선(굵게) · 이름(나 = "(나)") · 상태·경과 · 조작 하나(링잉 = [당겨받기]
`pickup(code, ext)` / 통화 중 & `monitorScope` 안 = [청취] / 청취 중 = «청취 중»). 칸을 누르면 번호칸에 채우고, 오른쪽 클릭 = 사람 메뉴.
- 소스: 그룹원마다 `dialogWatch(acc, ext, true)`(RFC 4235) → `onDialogInfo`. 대표번호 AoR 도 구독(대기열). 구독 순서는 **대표번호 → 감시 대상 전원**(엔진 슬롯이 모자라면
  앞쪽이 산다), 실패는 줄마다 로그 + 토스트 한 번("회선 감시 구독 실패 n건"), 다음 편성 재적용 때 재시도.
- **dialog 종료 규칙**: dialog id(Call-ID+태그)는 양 당사자에게 같은 하나 — `terminated` 는 entity 가 무엇이든 그 id 의 행 전부에 적용(NOTIFY 하나가 유실돼도 잔류 행 없음).
  `version`(RFC 4235 §4.1)은 **구독(Call-ID) 단위**로 비교한다(앱 재기동 뒤 이전 세션의 스테일 구독 NOTIFY 가 같은 entity 로 올 수 있다 — 엔진 481, 서버 즉시 회수).

**주소록**(탭 줄 [주소록] → 오른쪽 패널, §3.6) — 서버 회사 전화번호부(`service=volte`, 조직 칩 + 검색) + CSV 외부망 번호. 줄 = 이름 · 번호 · 조직 · BLF 상태 ·
[바로 걸기], 줄을 누르면 사람 메뉴. 외부망 번호는 접속서비스 트렁크 라우팅에 맡긴다(앱은 그냥 `dial`).

### 4.4 [무전] 메시지 · 이벤트 / [통화] 기록

**[무전] 메시지**(아래 줄 왼쪽) — [mcdata_messaging.md](mcdata_messaging.md) §5 의 앱 동작. **대화 목록(300, 경계 끌기) : 대화**.
- 목록 머리: "메시지" · **[따라가기 ✓]**(기본 켬 — 채널 카드를 누르면 그 채널 대화로, 설정 `FollowChannelThread`) · **[＋ 새 대화]**([사용자] 패널 — 사람 메뉴 [무전 메시지]) ·
  거르기 **[전체|그룹|1:1|안 읽음 n]**. 줄(60) = 아바타(그룹 = 모서리 8, 1:1 = 원) · 이름(안 읽으면 굵게) · [그룹]/[1:1] 라벨 · 마지막 말 미리 보기(«나: …» / «박경장: …» /
  파일 이름) · 시각 · 안 읽은 수. 고른 대화 = 왼쪽 3px 먹 띠 + 연한 면. 스레드 키는 그룹 = `groupUri`, 1:1 = 상대(`threadKeyOf` 규칙).
  **그룹 대화의 이름은 그룹 이름이다(키인 uri 를 내지 않는다)** — 지금 그룹 목록(멤버·청취 범위)의 이름을 쓰고 목록이 바뀌면(추가·삭제·이름 변경) 따라 바뀐다.
  목록에서 사라진 그룹(삭제됐거나 내가 빠진 그룹)의 남은 대화는 **주고받던 때의 이름**(메시지와 함께 보관 — `group_name`)으로 서고, 그 이름도 없으면 그룹 id 로 선다.
- 대화 머리: 이름 · 라벨(그룹 = 먹 채움 "그룹 전원 · 편성 n", 1:1 = 외곽선 "1:1") · 부제("접속 n" / "PTT <번호>") · [채널 정보 ›](그룹 — 채널 상세).
  목록에 없는 그룹의 대화는 라벨 "목록에 없는 그룹" · 부제 "삭제됐거나 내가 빠진 그룹" 이고 [채널 정보 ›] 가 없다(발신은 서버가 판정한다).
  말풍선(받은 말 = 회색 + 그룹이면 보낸 사람, 보낸 말 = 남색 + 상태 `보내는 중 → ✓ → ✓✓` / `· 실패` [재전송]) · 파일 말풍선 · **빠른 답**(«확인했습니다» · «이동 중» ·
  «도착했습니다» · «대기 바랍니다» — 한 번 눌러 곧바로 보낸다) · 입력(자리표시 "그룹 전원에게 (순찰1 · 12명)" / "이 사람에게 (윤순경)") · [📎] · [보내기](Enter, Shift+Enter 줄바꿈).
- 발신 그룹 `sendGroupSds(acc_ptt, groupId, text, requestDelivery)` / 1:1 `sendSds(acc_ptt, peer, …)` → `(msgId, token)` · 최종 응답 `onRequestCompleted(MESSAGE, token)` 을
  **token 으로** 상관해 2xx=SENT (자동 회신하는 disposition 통지의 완료 이벤트는 어느 메시지에도 맞지 않아 무시) · disposition 요청 수신은 `sendSdsNotification(delivered)` 자동 회신(대상 = 받은 SDS 의 `FromUri`, 그룹 SDS 면 `GroupUri` 를 넘긴다 — PTT 계정에 MCData PSI 가 있으면 코어가 참여 기능 PSI·`resource-lists`·`<mcdata-calling-group-id>` 규격형으로, 없으면 원 발신자 직행으로 보낸다, TS 24.282 §12.2.1.1) ·
  `onSds(notification)` 을 msgId 로 상관 → ✓✓. 재전송은 **처음의 msgId** 로 보낸다(`sendGroupSds`/`sendSds` 의 `msgId` — 앞 발신이 일부에게 닿았어도 받는 쪽이
  같은 메시지로 대조하고 ✓✓ 도 그 ID 로 맞물린다; 즉시 실패로 ID 가 없던 메시지만 새 ID) — token 만 새로 덮어쓴다. 그룹 본문이 프로파일 `mcdata.maxPayloadSdsCplaneBytes`
  를 넘으면 코어가 media plane(MSRP, TS 24.282 §9.2.3)으로 보내고 최종 결과가 `onRequestCompleted(MSRP, token)` 으로 온다(같은 token 상관). PTT 계정은
  `mcdataMsrp` 로 서버발 MSRP 배포도 받는다(`SdsMessage.MediaPlane`). 1:1 대화(개별 통화 상대·사람 메뉴 [무전 메시지]·받은 1:1, 키 = 상대 번호 user part)도
  글·파일을 보낸다 — 받은 1:1 은 코어가 request-type(`one-to-one-*`)을 보고 `groupUri` 를 비워 준다. 빠른 답도 같은 발신 경로다.
- **파일(FD, [mcdata_messaging.md](mcdata_messaging.md) §4.5)**: [📎](다중 선택)·말풍선 영역에 끌어 놓기 → 말풍선을 먼저 세우고("올리는 중…") 전용 CSC 핸들로
  `uploadFd`(그룹 = `group` 지정 — 서버가 `allow_fd`·멤버십 게이트, 1:1 = 없음) → `sendGroupFd`/`sendFd`(FILEURL·name/size/type) → token 상관은 글과 같다.
  상한 50 MB(서버 `McDataFd.MaxBytes` 기본) — 넘으면 읽기 전에 막는다. 재전송 = FILEURL 이 없으면 업로드부터, 있으면 알림만. 받은 파일은 이름·크기 + [받기] — 관제석은
  자동으로 받지 않는다(그룹 파일이 쌓이는 자리라 관제사가 고른다). 받기 = `downloadFd`(FILEURL 의 경로만 취해 **자기 CSC** 로 — Bearer 를 다른 호스트로 보내지 않음) →
  `다운로드\CIMS\<이름>`(겹치면 "(n)") 저장 후 연결 프로그램으로 열기, 이름 클릭 = 열기(안 받았으면 받기), 폴더 아이콘 = 탐색기에서 보기. 거부 사유는 §9 `Area.File`
  (`allow_fd` 꺼짐·비멤버·413·보관 만료).
- 보관: 로컬 SQLite(`%APPDATA%\CIMS\dispatch-desktop\messages.db`) 최근 30일(설정). 안 읽은 수는 카드 수 배지 · 세그먼트 [무전 n] · 레일 [관제] 수에 합친다.
  **격리 단위 = 로그인 ID**(`owner` 열 — 관제석은 자리별 로그인 ID 라 교대해도 같다): 조회·읽음 표시·새 행은 지금 로그인 ID 의 것만, 한 PC 에 다른 자리 ID 로
  로그인하면 앞 ID 의 대화가 보이지 않는다(재로그인 때 다시 읽음). 보존 정리(`Prune`)·재기동 PENDING 마감은 주인 무관. `owner` 열 이전 판의 행은 그 PC 의
  첫 로그인 ID 에 한 번 귀속한다(자리 PC 는 같은 자리 ID 로 로그인한다).

**[무전] 이벤트**(아래 줄 오른쪽) — PTT 세계에서 **방금 일어난 것**의 흐름. 진행 중 상태는 카드가 맡고 여기는 이벤트만.
- 머리: "이벤트 n" · **[따라가기 ✓]**(기본 켬 — 새 줄이 오면 맨 위로, 설정 `FollowEvents`) · [이력에서 보기] · [CSV]. **종류 칩**(켜고 끄기, 수 병기) =
  [발언](floor Granted→Idle — 누가·몇 초) · [입퇴장](멤버 합류/이탈(로스터 diff)·세션 시작/종료·개별/애드혹 통화 시작·종료·청취 시작/종료(관제사 자신)·내가 연 통화의
  **미응답 멤버 n명**(서버 INFO `<non-acknowledged-user>`, TS 24.379 §6.3.3.3 — `onNonAcknowledgedUsers`, 토스트 함께)) · [긴급](긴급/임박 개시·해제·긴급 경보 발령·해제
  (`onEmergencyAlert`)) · [SDS](발신자·요약) · [오류](발언 요청 거부·발언권 회수·요청 시간 초과 — floor 사유) + **[채널 · 전체 ▾]**(채널 하나로 거르기).
  칩마다 종류 색 점(발언 녹색 · 입퇴장 파랑 · 긴급 빨강 · SDS 청록 · 오류 빨강)이 있어 표 종류 라벨의 범례가 된다.
  «멤버 확인 전 연결»(개시 200 OK `P-Answer-State: Unconfirmed`, RFC 4964 — §10.1.1.2.1.1 2A))·그룹 생성/삭제는 종류 칩 밖(«기타» — 칩으로 숨기지 않는다).
- **고정 줄**: 진행 중인 긴급·임박 세션(경과 · 라벨 · "상황실 진행 중" · [채널로]) — 목록 위.
- **표**: 시각(초까지) | 채널 | 종류(라벨 = 칩 점과 같은 색 — 발언 연한 녹색 · 입퇴장 연한 파랑 · SDS 연한 청록 · 긴급 빨강 채움 · 오류 연한 빨강) | 내용(오류는 빨강 글자). 칸이 좁으면(작은 창) 채널 열을 접는다. 줄을 누르면 이벤트 상세(§3.6).

**[통화] 기록**(오른쪽 칸) — 일반통화 내역과 문자(SMS·LMS)를 **상대별**로 한 줄기에 묶는다. 시간순 표(응답·종료·울림 열)는 두지 않는다 — 끝난 통화의 날짜 조회는

- 머리: "기록" · 거르기 **[전체|통화|문자|부재 n|대표번호]** · [CSV]. **오늘 한 줄**: 응대 n · 부재 n(빨강) · 발신 n · 전달 n · 감청 n · 문자 n · [이력에서 보기 ›].

  terminated = 응대(응답자 = 같은 발신자와 confirmed 된 그룹원 회선, 내가 받은 호는 내 세션 행이 대신), 직접 착신 부재는 내 세션 기준. 서버 통합 이력(§13)의 대표번호

- **상대 목록**(300, 경계 끌기): 줄(62) = 아바타 · 이름(가입자면 부제 번호, 대표번호로 온 호면 "대표 7000") · 마지막 사건 라벨(통화 중 녹색 · 부재 빨강 · 착신/발신 ·

### 4.5 관리 화면 ([관리] F4)

조직·구성원·VoLTE/VoIP/PTT 번호·전화 그룹. 활성 조건 = `dispatch.directoryWrite`(전환기 `directoryAdmin`) = `own`\|`all`(관제 역할 **관리 범위** — 콘솔 `관리 > 역할`, manager 부여).
관제 화면과 같은 시각 언어(§3.2 — 알약 버튼 · 19px 라벨 · 아바타 · 흰 카드, [PTT 그룹] 화면 §4.7 과 같은 낱말)의 **세 카드**(서브내비 없음 — 항목이 하나뿐이고, 관리 범위는 화면 머리에 보인다).

**절 카드 넷**(연한 면 — [PTT 그룹] 폼과 공용 스타일 `FormCard`·`FormLabel`·`Field.Form`…, `Themes/Controls.xaml`): «기본»(이름·직함·소속·로그인 아이디/비밀번호) +
**회선 카드 셋 = VoLTE 번호(이동) / VoIP 번호(유선) / PTT 번호**(카드 머리 오른쪽에 저장된 회선 상태 라벨 «개설됨»(녹색)/«미개설» · 번호·접속서비스·SIP transport·SIP 비밀번호 — 비우면 회선 삭제,
새 회선·번호 변경·접속서비스 변경은 비밀번호 필수(서버가 H(A1) 로만 보관)) + PTT 카드의 자격 스위치(그룹 생성·원격 청취 — 청취는 표시만, 역할 배정의 결과) + 바닥 고정 [취소][저장](알약 — 스크롤과 무관하게 늘 보인다).
조직 폼 = 머리(폴더 아바타 · 이름 · "조직 편집 · 코드"/"새 조직 등록") + 절 카드 «조직»(코드(불변 키) · 이름 · 상위 조직 · 정렬 순서) + 바닥 [취소][저장].
**오류 문구**는 폼이 열려 있으면 폼 바닥([저장] 옆), 아니면 구성원 머리의 연한 빨강 띠에 뜬다.
회선 종류(와이어 kind `volte`·`voip`·`ptt`)는 `members[].{kind}`·`services.{kind}[]`·`PUT …/members/{id}/{kind}`·목록 열까지 한 축으로 갈라진다 — 서버가 종류당 첫 회선만 내리므로 이동·유선 회선을 둘 다 가진 관제사도 둘 다 관리된다.
카드별 차이는 콘솔 매트릭스와 같다: VoIP 카드 = `voip` 후보만 · 기본 TLS 에 UDP/TCP/TLS/**ANY** 선택 · IMSI 는 서버가 번호 숫자로 · 인증 digest 만 · `voip` 접속서비스는 **필수**(서버 400 `service_ref required for voip`·다른 kind 서비스는 `service_kind_mismatch`) · **픽업 그룹은 읽기전용 표시**(콘솔 전화 그룹 멤버십에서 서버가 파생 — 현행 와이어 `{msisdn,imsi,serviceRef,sipTransport,authScheme}` 에는 없어 서버가 `pickupGroup` 을 실어 줄 때만 보인다. 내선은 서버 엔티티가 아니라 주소록 표시 라벨(§13)); VoLTE 카드는 AKA 를 다루지 않는다(digest).
오류 문구 사전(`ResponseText.ForManagementError`)은 서버 토큰을 그대로 받는다 — `number_exists` 는 `where`(가입 테이블 이름 | `phone_groups` = 대표번호 주소 공간)로 문구를 가르고, `schema_not_migrated` 는 detail 의 `voip_subscriptions` 로 유선 테이블 미이관을 구분한다.
SIP transport 콤보는 **ANY** 를 포함한 넷(콘솔 라벨과 같다) — ANY 는 "가입자 override 없음(서버 NULL, 접속서비스 기본을 따른다)" 의 **양방향 명시값**이라 다른 값에서 되돌릴 수 있다. transport 만 바뀐 회선도 PUT 한다(H(A1) 무관, 비밀번호 불필요).
접속서비스 후보 = 서버 `services.<kind>[]`(항목이 `kind` 를 실으면 그것을 따른다 — 전환기 서버는 voip 항목을 volte 버킷에 함께 실었다). 기존 회선은 **저장된 서비스를 그대로 선택**(후보에 없으면 그 이름을 후보에 넣어 보인다, 저장값이 비면 비움 = 서버가 현재값 유지) — 첫 후보로 바꿔 넣으면
저장마다 "서비스 변경 → 재결박 비밀번호 필요(400)" 가 나기 때문. 같은 번호 PUT 은 저장된 IMSI 를 그대로 싣고(서버는 IMSI 가 없으면 번호 숫자로 채워 "IMSI 변경" 으로 오판), 번호가 바뀌면 새 회선이라 비운다.
바뀐 것이 없는 회선은 보내지 않는다. 후보가 0건이면 카드에 경고(서버 csc.json `Provisioning.Services` / access_services 미러 — server_todo T9)하고 회선 개설 저장을 앱에서 막는다. 서버의 문장형 오류
(`passwd required when imsi or service_ref changes` 등)는 `ResponseText.ForManagementError` 접두 매칭으로 번역한다.
저장 뒤 한 벌 재조회 + 전화번호부 동기화. 서버 계약 [android_ue_provisioning.md §3-3](android_ue_provisioning.md) — 범위 밖 403·번호 충돌 409 등은 서버 판정, 앱은
사전(`ResponseText.Area.Management`) 문구.

- 앱은 범위 enum 을 해석하지 않는다 — 서버가 걸러 준 조직·구성원만 보이고, 쓰기 판정도 서버가 한다.
- 폼 값이 열 때와 달라진 동안(`IsDirty` — 클릭만으로 폼이 열리므로 열림≠변경) 레일 [관리] 에 점 배지, 화면 머리에 "저장하지 않은 변경". 관제로 다녀와도 폼은 유지된다(§3.4).
  변경이 있는 채로 다른 구성원을 클릭하면 "변경 버림" 확인 — 아니오면 선택이 되돌아간다.

### 4.6 이력 화면 ([이력] F2)

끝난 통화·PTT 세션의 **날짜 창 조회 + 녹취 재생**. 활성 = 관제 역할 있음(범위는 서버 역할 `monitorCall`/`pttListen`). 진행 중·오늘의 실시간 흐름은 [관제] 가 정본이고
«이벤트»·«기록» 머리의 [이력에서 보기]가 종류(PTT 세션 / 통화)를 맞춰 이곳으로 넘어온다.

내용은 콘솔 `/service/history/volte`·`/service/history/ptt` 와 같은 자료(콘솔의 SIP Flow 다이어그램은 운영자 진단용이라 싣지 않는다)이고, 모양은 관제 화면의
시각 언어를 따른다 — 무전·통화 모두 **왼쪽 카드 목록(시간대 묶음) + 오른쪽 상세 패널**(목록 1 : 패널 3, 경계 드래그로 조절·더블클릭 = 기본)이다.
**영상도 같은 화면에 든다** — 영상 통화(VoLTE 영상, `callType: volte_video`)는 [통화] 목록에 «영상» 태그·종류 «영상» 으로, 영상 세션(MCVideo 그룹 호 — 같은 그룹의
영상 호, `service: mcvideo`)은 [무전] 목록에 «영상» 라벨로 서고(콘솔 PTT 이력이 두 서비스를 한 목록에 서비스 배지로 보이는 것과 같다), 영상이 있는 녹취를 틀면
오른쪽에 **영상 칸**이 열린다.

- 도구줄: 종류 = 관제 탭 줄과 같은 **[무전 | 통화]**(`ModeSeg` — 같은 순서·남색 외곽선 안 고른 칸 남색 채움, 처음은 무전) · 날짜 [◀] DatePicker [▶] [오늘](하루 단위
  창 조회 — 서버 스캔 48 시간 버킷 상한, 미래로는 못 간다) · 검색(이름·번호·그룹) · 무전만 서비스 거르기 칩 **[전체 | 무전 | 영상]**(음성 무전 MCPTT 세션 / 영상 MCVideo
  세션 — 받은 항목에 서비스 축 `service` 가 실려 있을 때만 보인다) · 무전만 토글 칩 **[빈 세션 묶기]**(기본 켬 — 아래 «빈 세션 묶음») ·
  요약(세션 건수·진행중·녹취·영상 n건·PTT 발화 합·빈 세션 n건 → m묶음) · 새로고침 아이콘. 종류·날짜가 바뀌면 자동
  조회하고 시간대 필터는 해제된다. 화면 머리 힌트 = "지난 통화·무전 기록과 녹취 · 관제 그룹 <이름> 범위". 창 조회 결과는 앱 로그에 한 줄로 남긴다
  (`history window ptt 2026-10-01: 37 items (mcvideo 3, service axis yes) · query 820 ms · list 12 ms · render 95 ms` · 통화는 `(video n)`) — "콘솔에는 있는데 앱에는 없다" 를
  서버 응답에서 가르고, 느릴 때 서버 응답(query)·목록 만들기(list)·화면 그리기(render) 중 어디인지 가르는 근거.
- **시간대 밴드**(도구줄 아래 전체 폭, 24칸): 그날의 분포이자 필터 — 칸 클릭 = 그 시간대만(무전 [발언 수] 에서는 **그 시간대의 발언 있는 세션만** — `turnCount` > 0
  또는 녹취 있음, 요약에 "HH시 발언 있는 세션"), 다시 클릭·[전체 시간] = 해제(그 모드에서 0 인 칸은 무시 — 칸 옆 안내 글이 모드에 따라 뜻을 적는다). 농도는 그날 가장 많은
  칸 대비 연한 남색(글자가 늘 읽히는 범위), 고른 칸 = 남색 테두리 2.5(관제 카드 선택과 같다), 툴팁 = 무엇을 센 건지("14시에 시작한 무전 세션 11건").
  제목 = 센 것: 통화 = **시간대별 통화 횟수**(응답 `hours` — INVITE 시각) · 무전 = **시간대별 무전** + 세그먼트 **[세션 수 | 발언 수]**(기본 세션 수 — 제목 글자가 모드와
  상관없이 같아 전환 자리가 움직이지 않는다): 세션 수 = 응답 `hours`(세션 시작 시각, limit 절삭 전 전체) / 발언 수 = 받은 세션들의 발언 턴 `turnCount` 를 세션 시작 시간대에
  더한다 — 턴의 실제 시각으로 나누지 않는다). 하루 상한(1000건)을 넘어 받은 세션이 `hours` 보다 적은 시간대는 덜 센 값이라 칸에 "+" 를 붙이고 툴팁에 못 센 건수를 적는다.
- **목록 카드**(관제 채널 카드 §4 공통과 같은 모양 — 모서리 10·테두리, 고른 카드 = 남색 테두리 2.5 + 연한 남색 면, 긴급 = 빨강 테두리 2 + 연한 빨강 면), 최근이 위,
  **시간대 묶음** 머리 "HH시 · n건"(밴드와 같은 축). 이름이 길면 이름만 줄이고 라벨·시각은 오른쪽에 붙는다. 목록은 묶음 상태에서도 **가상화**한다(보이는 카드만 만든다 —
  하루 상한 1000건을 다 만들면 십여 초가 걸린다. `PlainList` 는 `IsVirtualizingWhenGrouping` 을 켠 묶음 목록을 항목 단위로 굴린다). 머리 건수는 행 수가 아니라 세션 수다
  (빈 세션 묶음은 묶은 수). 거르기·펼치기를 바꿔도 고른 세션이 목록에 남아 있으면 선택과 상세 패널(재생 포함)이 그대로다 — 묶음에 접혀 들어가면 그 묶음 머리를 고른다.
  - 통화 카드(두 줄): 결과 태그(응답 회색 · 통화 중/호출 중 초록 · 부재/실패/취소 주황 · 거절/오류 빨강 — 응답 시각이 있으면 응답, 없으면 종료 사유 no_answer/timeout = 부재,
    busy = 실패, rejected = 거절, error/incomplete = 오류, 그 밖 = 취소) · 발신 → 착신(이름 있으면 이름) · 영상/긴급/녹취 · 호출 시각 / 둘째 줄 = 통화 시간 · 울림 또는 끝난 이유 · 울림.
  - 무전 카드(세 줄): 상태 점(진행 중 초록) · 대상(그룹 이름 / 1:1 `A ↔ B` / 임시 `A 외 n명`) · 영상/개별/애드혹/전이중/진행 중/긴급/녹취 · 시작 시각 / 개시·참여 n명 /
    길이 · 발언 n회 · 말한 시간. **영상 세션**은 «영상» 라벨(청록)이 붙고 셋째 줄이 "길이 · 송출 n회 · 보낸 시간" 이다(MCVideo 는 발언권이 아니라 송출 허가 — TS 24.581).
  - **빈 세션 묶음**([빈 세션 묶기] 켬, 기본): 누가 호를 열고 아무도 말하지 않아 유지 시간(T4)이 지나 닫히는 일이 되풀이되면 목록이 같은 카드로 덮인다 — 목록에서
    **연달아 나오는** 같은 시간대·같은 서비스·같은 그룹·같은 개시자의 **빈 세션** 2건 이상을 카드 한 장으로 묶는다(사이에 다른 세션이 끼면 거기서 끊겨 시간 순서는 그대로,
    한 건뿐이면 묶지 않는다). 빈 세션 = `turnCount` 0 이고 녹취도 없는 종료 세션 — 진행 중이거나 항목에 `turnCount` 가 없으면 아니다(녹취를 같이 보는 것은 세션 인덱스가 없어
    발언 수가 늘 0 으로 오는 스캔 폴백에서 말한 세션을 묶지 않기 위해서다). 묶음 카드 = 뒤에 겹친 카드 두 장 · 대상 · «빈 세션 n건» 태그 · 가장 이른~가장 늦은 시작 시각 /
    개시·참여 n명 / "각 30~31초 · 발언 0회"(영상 세션은 송출) + **[n건 펼치기]**. 카드를 고르면 가장 최근 세션이 열린다. 펼치면 카드 아래에 한 줄씩(시각 범위·길이 · 발언 0회)
    붙어 하나씩 고를 수 있고 [접기] 로 닫는다(펼침은 묶음마다 — 시간대 + 가장 이른 세션이 열쇠라 새 세션이 위에 붙어도 펼친 채). 끄면 한 장씩 나온다.

  툴팁에 사람별 합 · 있을 때만 최대 동시 발언 · 녹취 세그먼트 수) →
  ① 참여자(입퇴장 기록 ∪ 화자 — 관제 화면의 이름표: 아바타 색 = 이름, 개시 태그, 말한 사람은 레인 색 점·발언 n회, 입장~퇴장은 툴팁) → ② 발언(화자 레인 위 턴 막대, 세션 시간축 + 눈금 행 — **막대 클릭 = 그 발언부터 재생**(재생 바와 같은 헤드 — 줄인 틈 축에서도 막대의 실제 시각으로),
  동시 발언 세그먼트는 단독 트랙 `slot`. **[틈 줄임]**(기본 켬) = 말이 없는 구간(세션 머리·꼬리 포함)을 짧게 접어 말한 구간을 넓게 본다 — 접는 상한 = 발언 시간 합의 5 %(1.5~15초),

  발언 덩어리가 시작하는 시각. 끄면 시간에 비례한 축(눈금 간격은 배율에 따라 1초~1시간 중 자동). **확대·축소** = [−]·[+]·[1:1] 버튼 / Ctrl+휠(커서 기준) ×1.25 단계·최대 ×64,

  거절 사유·회수 유예) → 녹취 재생 바(아래 고정, 아래 «녹취 재생 바» — 재생 바 막대는 틈 줄임과 무관하게 시간에 비례한다). 세 구획은 칸이 낮으면(작은 창·배너 둘) 0 으로 눌리지 않게 최소 420 을 두고 세로로 넘긴다.

  지표·종류·참여자 수는 목록 항목의 확장 필드에서 온다(서버가 OAM 세션 인덱스를 범위 게이트 뒤에서 프록시 — 스캔 폴백이면 지표 0).

  호 방식·동시 송출 상한("chat · 동시 송출 2"), 숫자 칸 = 송출 회·보낸 시간·최대 동시 송출, ② 가 «송출»(누가 언제 영상을 보냈나 — 세그먼트 = 송출 구간, 화자 구간은 음성 트랙에서
  읽고 음성 없이 영상만 있는 구간(송출 중 무전으로 마이크를 넘긴 동안 — mcvideo.md D12)은 영상 트랙에서 읽는다), 참여자 이름표 "송출 n회".
- **녹취 재생 바**(통화·무전 상세 패널 맨 아래 고정, 공용 `PlayerTpl`): 막대 하나 = 녹취 전체의 벽시계 구간(통화 = 첫 세그먼트 시작~마지막 끝, 무전 = 세션
  시간축 — 발언 레인과 같은 축). 재생하면 막대가 차오르며 `지금 / 전체`(mm:ss)와 그 순간의 실제 시각을 보인다. **막대를 누르면 그 지점부터**(시각 → 그 시각을 담은 세그먼트 +
  파일 안 오프셋), 마우스를 올리면 그 지점 시각(무전은 + 그때 말한 사람)을 말풍선으로. 조작 = [재생/일시정지] · 통화 [−10초]·[+10초] / 무전 [이전 발언]·[다음 발언] ·
  속도 [1× 1.5× 2×](`MediaElement.SpeedRatio`) · [다시 변환](failed 표식 제거 후 그 자리에서). 무전 막대 위에는 **발언 막대**(화자 레인 색, 겹치는 동시 발언은 두 번째 줄)와
  재생 헤드, 조작 줄 끝에 "지금 <이름> · 발언 #n"/«말 없는 구간», **말 없는 구간 건너뛰기**(기본 켬 — 끄면 세그먼트 사이 빈 시간을 시계로 흘려 다음 세그먼트에서 이어 튼다).
  세그먼트가 끝나면 다음 세그먼트로 이어진다. 발언 레인의 턴 막대를 누르면 그 발언 시작으로 옮겨 재생(믹스). 머리 [처음부터] = 첫 세그먼트부터.
  파일은 세그먼트별 MP4/AAC(`/provisioning/recordings/{id}/segments/{seq}/audio` — 202 변환 중이면 0.7→1.5초 간격 최대 120초 대기 문구)를 로컬 캐시에 한 번 받아
  쓰므로 이리저리 옮겨도 다시 받지 않는다. 재생기는 열린 뒤(`MediaOpened`)에 위치·속도·멈춤을 걸고, 창이 200 ms 마다 위치를 VM 에 알린다(`Tick`).
  **영상 칸** — 세그먼트에 영상이 있으면(`has_video` — 영상 통화 녹취·MCVideo 송출 구간. 서버가 내는 MP4 는 음성 AAC + 영상 H.264 한 파일이다) 그 세그먼트가 열려 있는 동안
  상세 패널 오른쪽에 «녹취 영상» 칸(372)이 열려 그 영상을 그린다(비율 유지, 머리 [정지]·재생 중 표시, 아래 `지금 / 전체 · 실제 시각`). 재생 바가 그대로 조작한다(누른 곳·속도·
  일시정지 — 일시정지는 칸을 닫지 않는다). 영상 없는 세그먼트·말 없는 구간으로 넘어가거나 [정지] 하면 닫히고 왼쪽 두 칸이 원래 폭으로 돌아온다. 소리만 있는 녹취는 칸 없이 소리만 난다.
  재생은 로컬 내역 링 버퍼(CSV 내보내기)에 "녹취 재생" 행, 서버 감사 `E-AUD-016 tap_mode=recording`. 임시 파일 `%TEMP%\CIMS\dispatch-desktop\rec`(화면을 떠날 때
  6시간 지난 것 정리). 화면을 떠나거나 별창으로 옮기면 재생은 멈춘다.
- 서버 계약 [android_ue_provisioning.md §3-2/§3-2a/§3-4](android_ue_provisioning.md). 구현 `ViewModels/SessionHistoryViewModel.cs`(`HistoryRow`·`HourCell`·
  `SpeakerLane/TurnBar`·`TimelineItem`, 표시 사전 = 콘솔 `pttSession.tsx` 의 EVENT_ICONS/FLOOR_OPS/DENY_REASON 문구) · `Views/HistoryView.xaml`.

### 4.7 PTT 그룹 화면 ([PTT 그룹] F3)

관제 화면과 같은 시각 언어(§3.2 — 알약 버튼 · 각진 필터 칩 · 19px 라벨 · 아바타 · 흰 카드)의 두 카드 — 왼쪽 **그룹 목록**(1 : 3, 300~420, GridSplitter), 오른쪽 **선택 그룹 카드**.
목록 머리 = «그룹 N» · [↻](아이콘) · **[+ 새 그룹]**(먹 알약) / 검색(그룹 이름·id, 돋보기) / 필터 칩 [전체|멤버|내 소유]; 행(62) = 그룹 아바타(모서리 8, 색 = 이름 해시) · 그룹명 +
관계 라벨(멤버 = 연한 남색 › 청취 범위 = 청록 › 소유 › 범위) · 인원 / id · 소속(조직 경로) · 서비스 칩 «음성»·«영상». 오류·«편집 중» 안내는 목록 머리의 연한 면 띠.
**행 한 번 클릭 = 상세**: 머리 = 아바타 46 · 이름(19 굵게) · 라벨([멤버]/관계 · [영상] · [세션 진행 중]) · 둘째 줄 id · 소속 · 오른쪽 **[채널로]**([관제]·[무전] 으로 돌아가 그 채널 상세를
연다 — 멤버 그룹은 내 채널 카드, 청취 범위 그룹은 타 채널 행, 합류하지 않는다) · **[편집]**(먹 알약) · **[삭제]**(빨강 외곽선) — 뒤 둘은 `canManage` 행만. 본문 = **정보 칸 여섯**(연한 면 —
소유자(내 것은 "이름(나)", 나머지는 문서 GET 이 채움) · 소속 · 세션 종류 · 그룹 우선순위 · 긴급(긴급 통화·긴급 경보 허용) · 청취 노출(은닉/투명)) · **능력 칩**(MCPTT 음성 · 메시지(SDS) ·
파일(FD) · MCVideo chat/편성 · 송출 n · 암호화 · affiliation 필요) · «멤버 N» / «affiliation M» 과 **멤버 2열**(아바타 · 이름 · (나) · [의장] · 번호 / 상태 = [발언 중] 녹색 라벨 · 참여(녹색 글자) ·
미참가(줄 흐림)) — 참여 › 미참가 순, 로스터·발언은 1초 틱으로 갱신 · 바닥 = 목록 범위 안내 한 줄.
**[편집]·[+ 새 그룹]·행 더블클릭 = 같은 카드 자리의 인라인 편집 폼**(`GroupEditView`, 별창 없음) — 왼쪽 400 = 속성 **절 카드 넷**(기본: 이름·id·세션 종류 = prearranged/chat — 일제 통화는
호 속성이라 선택지에 없다·우선순위·최대 참가자 / 그룹 호 / 허용·한도(스위치 2열 + 크기 한도) / 서비스 — 아래 표) · 오른쪽 = 멤버 **카드 둘**(PTT 주소록(검색 · [표시된 전원 추가] · 행 [＋ 추가]) →
멤버 n명(필수·의장 토글 — 켜지면 채움 · [×] 빼기)) · 바닥 [취소][저장/그룹 만들기](알약).
편집 중엔 목록·[↻]·[+ 새 그룹]이 잠겨 편집 대상이 바뀌지 않는다(저장·취소로만 나온다). 저장 뒤 목록을 재조회하고 그 그룹(새 그룹이면 응답 uri 의 id)을 선택해 상세로 돌아온다.
관제 화면에서 드는 두 진입도 같은 폼이다 — [사용자] 패널 [그룹으로 저장 ›] 은 폼을 줄여 오른쪽 패널 «새 PTT 그룹»에 싣고([▸ 고급 설정] = 이 화면으로 넘어와
같은 폼을 이어 쓴다, §3.6), 채널 상세 ⋮ [편집]·Ctrl+K 그룹 [멤버 추가] 는 이 화면의 편집 폼으로 온다. 세 진입이 `GroupEditViewModel` 하나를 공유하므로 편집 중인 폼이 있으면
다른 진입은 "저장하거나 취소한 뒤" 경고로 막힌다.
목록 원천 = `GET /provisioning/directory/groups`(**관리 범위 안(org_code) ∪ 내 소유 ∪ 관제 그룹 청취 범위(`ptt_listen`) ∪ 내 멤버 그룹**, 멤버가 아니어도) — 행의 `canManage`(관리 범위 안 또는 내 소유,
서버 GMS 게이트와 같은 판정)가 참인 행에만 [편집]/[삭제]·상세 [편집…]이 보이고, 청취 범위·멤버로만 보이는 행은 보기 전용이다(조직 미지정 그룹이 `own` 범위에서 통째로 사라지지 않게).

  폼을 연 것만으로 서버 값을 명시값으로 굳히지 않는다. 값을 바꾸면 그 값(범위로 자른 값)을 싣는다.

  (서버 자원, 최대 8)을 잡는 운영 정책이고, 규격판(TS 24.581 Transmission Control)은 미구현이다.

## 5. 감청 · 청취 — 인라인이 기본, 감청 창은 선택

감청·청취는 켜는 자리가 곧 보는 자리다 — VoLTE 감청은 [통화] «진행 중» 행이 펼쳐지고(§4.3), PTT 청취는 [무전] 타 채널 행의 [청취 중] + 채널 상세(§4.2)다.
두 번째 모니터에 따로 두고 싶을 때만 **[창으로 ↗]** 로 감청 창을 띄운다(주 창과 별개의 비모달 `Window`, 기본 440×260, 크기 조절·이동, 위치는 `layout.json`).

| 종류 | 진입 | 인라인 표면 | 감청 창 내용 | 종료 |
|---|---|---|---|---|
| **VoLTE 감청** | «진행 중» 행·«관제 그룹원» 칸 [청취] → `join(dlg)` → `CallInfo.listenOnly && joinedDialog≠""` | 행 확장 — 은닉/투명 라벨(`listenVisibility`) · `caller`/`callee` 두 줄(RFC 5576 `label`) 이름·레벨 막대(`MediaSource.active/level` — U10 관측 API 후속 시 실시간, 그 전엔 `active`) · 출력 · 음량 · [창으로 ↗] · 행 머리 [청취 종료] | 제목 "감청 — A ↔ B" · 같은 두 줄 · 출력(기본 헤드셋) · [양쪽 ▾](표시용 — tap 모드는 서버 운용값) · [청취 종료] | [청취 종료]·창 닫기 = `hangup`. 원 통화 종료 → 서버 BYE → 행이 사라지고, 창은 "통화 종료됨" 3초 후 자동 닫힘 |
| **PTT 청취** | 타 채널 [청취] → `joinGroupCall(listenOnly)` | 행 [청취 중](먹 채움) · 채널 상세 "청취 전용 — 발언 요청 불가" · 음량 · 출력 · [청취 중지] · [창으로 ↗] | 제목 "청취 — 그룹명" · 배지 "청취 전용" · 발언자 이름·레벨·경과(`onFloor` Taken) · 참가자 수(`onRoster`) · 긴급 배지 · "발언 요청 불가(Permission=0)" 고정 문구 · 출력(기본 스피커) · 음량 · [청취 종료] | [청취 종료]·[청취 중지]·창 닫기 = `leaveGroupCall`. 480 이면 청취를 열지 않고 토스트 |

- 상단 바 **"감청 중 N" 칩**이 진행 중인 감청·청취를 전부 나열하고, 누르면 그 감청 창(없으면 연다). 창을 최소화해도 청취는 계속된다. 창 닫기(×)는 종료
  (설정 "닫기 전 확인"). 앱 종료로 닫힐 때는 다시 묻지 않는다 — 주 창 종료 확인이 진행 중인 것을 이미 세고(§6), Shutdown 중 취소는 무시되므로 두 번째 질문은
  종료만 붙잡는다(`App.IsExiting`). 재기동·재로그인 뒤 스냅샷 재구성은 감청 창을 다시 띄우지 않는다(인라인 표면이 바로 보인다).
- 감청 창은 포커스를 훔치지 않는다. 주 창의 착신·긴급 배너가 우선.
- 여러 청취의 소리는 라우트별로 섞인다 — 기본값이 VoLTE 감청 헤드셋 / PTT 청취 스피커인 이유. 동시 청취 상한 기본 4(설정, 타 채널 머리에 n/상한).
- 앱은 감청 이력을 로컬 내역(«이벤트»·«기록» 의 청취 시작/종료 줄)에만 남기고 감사 정본은 서버(`E-AUD-016`).
- 감청 영상(후속 — §10.7): VoLTE 감청 창 아래 격자(caller | callee)가 붙어 창이 커진다.

## 6. 시작·로그인·프로비저닝

```
[시작] → 단일 인스턴스 확인(명명 Mutex, 둘째 실행은 기존 창 활성화)
      → 저장 토큰(DPAPI) 있으면 refresh → 없으면 로그인 창(아이디/비밀번호 → CscClient.login PKCE)
      → fetchProfile(/provisioning/me) → services[volte, ptt] → Engine.start → addAccount×2 → register×2
      → dispatch 블록 → 데스크 신원·범위 적용 → dialogWatch(그룹원·대표번호) · affiliate(멤버 그룹) · subscribeConference(멤버·청취 그룹)
      → 창 위치 복원(layout.json) → 메인 화면([관제]·[무전])
```

- 로그인 창: 아이디·비밀번호·CSC 주소(기본 마지막 값, 고급 접힘)·"자동 로그인"(refresh token 만 DPAPI 저장 — 비밀번호·H(A1) 는 저장하지 않는다;
  `sipHa1` 은 매 로그인 프로파일에서 받는다). 저장된 토큰은 **앱을 종료해도 남아** 다음 기동이 로그인 창 없이 이어 로그인한다(`resume()`). 지우는 것은
  [로그아웃]·자격 만료(`invalid_grant`·401)·자동 로그인을 끄고 한 로그인뿐이다. 기동 때 서버에 닿지 않아 이어 로그인하지 못한 것(망 단절·5xx)은 토큰을 남기고
  로그인 창에 사유를 보인다(다음 기동이 다시 이어 간다).
- `phoneGroup` 없음 → [통화] «관제 그룹원»·대표번호 대기열을 "전화 그룹 미배정" 으로 접는다. `dispatch` 없음 → 타 채널·«진행 중» 의 청취 조작·감청·이력·관리를
  "관제 역할 미배정" 으로 접고 PTT·통화·문자·발신은 동작(일반 소프트폰 모드). 콘솔 `구성 > 전화 그룹` / `관리 > 역할` 배정 안내.
  (전환기: 서버가 합성한 `dispatch` 블록 하나만 오면 `present` 하나로 둘 다 판정.)
- 등록 실패(401/403/타임아웃) → 상단 점등 빨강 + 토스트, 자동 재시도(백오프 5→60초).
- **망 전환·복귀** → 코어 `Engine.HandleNetworkChange`(TCP/TLS 연결 종료 + 등록을 켠 계정마다 재등록, 앞 등록이 걸려 있으면 끝난 뒤 한 번 더 — [ue_sdk.md §4.2](ue_sdk.md)).
  계정별 REGISTER 만으로는 옛 주소의 TCP/TLS 연결로 다시 나간다. 통지(`NetworkChange.NetworkAvailabilityChanged`·`NetworkAddressChanged`)는 가상 어댑터·IPv6 임시
  주소로도 잦아 `DispatchSession.NoteNetworkChange` 가 2초 합친 뒤 유니캐스트 주소 지문(루프백·터널·링크 로컬 제외)이 바뀌었고 망이 있을 때만 알린다.
  진행 중 호의 유지는 코어 과제([ue_sdk.md §11](ue_sdk.md)).
- **CMS 문서**(TS 24.484 user profile·service config — `CscClient.FetchUserProfile/FetchServiceConfig`, ETag 304) = 기동 때(PTT 계정을 올리기 전) + 5분마다.
  user profile ruleset → `Capabilities`(UX 선차단 — [긴급 호출]·[긴급 해제]·개별·애드혹·[경보 해제], 받지 못한 문서는 허용, 최종 판정은 서버 — 자격이 바뀌면
  카드·배너의 해제 버튼도 다시 판정한다), service config 의 `*-resource-priority` → PTT 계정 `Rp*`(없으면 코어 기본값). 엔진 `UdpNoTcpSwitch` = 올리는 서비스 중
  하나라도 `sip.udpNoTcpSwitch`.
- **UE initial configuration**(TS 24.484 §7.2 — `CscClient.FetchUeInitConfig(<기기 urn>)`, 로그인 전 문서라 토큰 없음, MCS UE ID = `+sip.instance` 와 같은
  `DeviceIdentity.InstanceUrn`) = 기동 때 PTT 계정을 올리기 전. 참여 기능 PSI 둘을 PTT 계정에 넣는다 — `McpttServerUri`(경보 Request-URI, TS 24.379 §12.1.1.1 8))·
  `McdataServerUri`(disposition 통지 Request-URI, TS 24.282 §12.2.1.1). 광고하지 않은 서비스·못 받은 문서는 비워 둔다(경보 = 그룹 URI, 통지 = 원 발신자 직행 —
  코어 전환기 경로).
- **관제 편성 추적**: 로그인 후 60초마다 `GET /provisioning/me` 를 `If-None-Match` 로 재조회한다 — 304 면 끝, 200 이면 `dispatch.members[]`
  (`groupId == dispatch.groupId` 가 «관제 그룹원» 칸, 나머지는 감시 전용)·`pttTargets[]`·범위를 비교해 바뀐 것만 dialog watch 해제/추가·conference 구독
  재적용 후 토스트 한 줄. 그룹원 번호는 망 주소(`volteAor`)이고 내선 라벨은 이름에 병기된다.
- **메인 창·ViewModel 은 앱 수명 동안 하나.** 세션·핫키·1초 틱은 싱글턴이라 로그인마다 VM 을 새로 만들면 이벤트 구독이 쌓인다(SDS 이중 저장·PTT 이중
  요청). 로그아웃 = 창 숨김(+감청 창 닫기·창 위치 저장) → 로그인 창, 재로그인 = 스냅샷 재구성 후 다시 표시.
- **기동 실패는 종료로 끝난다.** 데이터 폴더(`%APPDATA%\CIMS\dispatch-desktop`)의 `messages.db` 잠김·읽기 전용 등 기동 중 예외는 "기동 실패" 창을 띄우고
  프로세스를 끝낸다(창 없는 프로세스로 남지 않게). 주소록 CSV 가 잠겨 있으면 그 파일만 건너뛰고, 설정·배치 저장 실패는 조용히 삼킨다(메모리 값 유지).
- 로그아웃: 등록 해제 → 토큰 폐기 → 로그인 창. **창 닫기(×) = 종료**(메뉴 [종료] 와 같다 — 진행 중인 것이 있으면 확인, 저장된 자동 로그인은 남는다).
  **종료·로그아웃 확인은 관제사가 하고 있는 것만 종류별로 센다** — "진행 중: 통화 1 · 무전 2 · 감청 1 · 청취 1 · 영상 보내기 1 · 영상 보기 1"(0 인 종류는 뺀다, `DispatchSession.LiveSummary`).
  영상 채널 호는 앱이 내 채널에 맞춰 스스로 붙어 있는 것(§10 D10)이라 세지 않고, 영상을 보내거나(요청·대기 포함) 보고 있을 때만 센다 — 셀 것이 없으면 묻지 않고 끝낸다.
  설정 › 관제 «창 닫기(×)는 종료하지 않고 최소화» 를 켜면(기본 꺼짐) × 는 최소화이고 종료는 메뉴로만 한다. 설정 판(`UiVersion` 4)이 옛 기본값(최소화)을 한 번 끈다.

**세션 수명 — 자격은 둘이지만 로그인은 하나다.** 단말은 규격상 자격을 둘 든다: SIP 시그널링은
**H(A1) Digest**(TS 33.203, CSP 상대 — 재등록으로 사실상 안 죽는다), MC 서비스 인가는 **OAuth2 bearer**
(TS 33.180, CSC 상대 — `ACCESS_TOKEN_TTL` **1시간**, [mcx_identity_scope.md](mcx_identity_scope.md) §6).
밑단이 둘인 것은 규격이지만 **관제사가 겪는 세션은 하나여야 한다** — «통화는 되는데 조회만 안 되는»
반쯤 로그인된 상태를 두지 않는다.

| 사건 | 되살릴 수 있나 | 동작 |
|---|---|---|
| access token 1시간 만료 | 예 (refresh) | **보이지 않게 갱신.** 만료 60초 전 선제 + 401 을 받으면 강제 갱신 후 1회 재시도. 관제사는 몰라야 한다 |
| 갱신이 실패하는 중 (네트워크·5xx) | 일시적 | 옛 토큰 유지 + **경고 띠** — 조회를 누른 그 순간에야 튕기지 않게 미리 알린다 |
| `400 invalid_grant`·401 (폐기·회전 실패·refresh 만료) | **아니오** | **앱 전체 로그아웃** — SIP 등록까지 내리고 로그인 화면으로, 사유를 남긴다 |

- **refresh token 은 회전할 때마다 만료가 리셋된다**(csc `create_tokens` — `expires_at = now + REFRESH_TOKEN_TTL`).
  한 시간마다 갱신하므로 켜져 있는 동안에는 7일 만료가 오지 않는다. 문제가 되는 것은 앱이 **꺼져 있던**
  기간이고, 그때는 기동 시 `resume()` 이 실패해 정상적으로 로그인 창이 뜬다.
- **주의(서버)**: `IdMs.JwtSecret` 이 비어 있으면 CSC 가 재기동마다 임의 시크릿을 쓴다
  (csc `mcptt.py` — 그 설정의 help 가 "재생성 시 발급된 모든 토큰 무효화"). 그러면 재기동 때마다 모든
  관제석이 한꺼번에 튕긴다. 운영 설정에 값을 박아 둔다.
- **구현(양 플랫폼 같은 규칙)** — 토큰을 쓰는 곳은 **단일 창구 하나**를 지난다(`AccessTokenAsync` /
  Android `accessToken()`): 만료 60초 전이면 먼저 갱신하고, 1초 틱이 아무 조회도 없는 관제석의 토큰도
  살려 둔다. 갱신은 잠금 하나로 직렬화해(Windows `SemaphoreSlim` / Android `Mutex`) 동시에 여러 요청이
  깨어나도 한 번만 돈다. `ManagementClient`·`HistoryClient` 는 **401 을 받으면 그 토큰을 넘겨 강제 갱신한
  뒤 딱 한 번 재전송**한다 — 기다리는 사이 다른 호출이 이미 갱신했으면 그 결과를 쓰고 갱신을 또 하지
  않는다. 일시 실패는 옛 토큰을 유지한 채 경고 띠(`BannerKind.Credential`)만 올리고, `invalid_grant`·401 은
  `CredentialsEnded` 로 **앱 전체 로그아웃**(등록 해제·창 전환은 셸이 하고 사유는 다음 로그인 창에 뜬다).

- 설정에서 재배치, 충돌(`RegisterHotKey` 실패)은 빨강 표시. 해석되지 않는 문자열(`HotKey.TryParse` 실패)은 행에 "형식 오류"를 띄우고 [저장·적용]을 막는다
  (조용히 등록만 빠지는 일이 없게). 게임패드/풋스위치는 HID 키 매핑으로 같은 경로.
- PTT 키 hold 중 포커스가 바뀌어도 release 를 놓치지 않도록 — 전역 키는 key-up 폴링 20ms, 창이 받는 키는 뗌(KeyUp)과 **앱이 뒤로 갈 때**(Deactivated) 놓는다 +
  안전장치(Granted 후 `TalkLimit` 는 코어가 자동 Release).
- **글자 키**(Ctrl/Alt/Win 없이 누르는 Space·Enter·Tab·글자·숫자·숫자패드·문장부호 — `HotKeyMap.IsTypingKey`)는 전역 이름(PTT·응답·종료·그룹 픽업)에 넣어도 **전역으로 등록하지 않는다** —
  등록하면 다른 프로그램의 타이핑을 삼킨다. 그런 키는 앱이 앞에 있을 때 창의 키 처리가 받고(`HotKeyMap.FocusOnly` — 충돌 표시 아님, 설정 행에 "앱이 앞에 있을 때 · 입력칸 밖"),
  누르고 있는 동안의 반복·뗌도 삼킨다(흘리면 포커스가 있는 버튼·체크가 그 키로 눌린다 — PTT 가 Space 인 동안 버튼은 Enter 로 누른다). F키·Pause·ScrollLock 등은 수식키 없이도 전역이다.
- **입력란 규칙**: 텍스트/비밀번호 상자에 포커스가 있을 때 앱 포커스 핫키는 **글자를 넣는 키(수식키 없는 비-F키)만 양보**한다 — PTT 기본 키 `Space` 도 입력칸에 커서가 있으면 빈칸으로 들어간다.
  관리 화면은 입력 폼투성이라 여기서 전부 버리면 전역 등록 실패(충돌) 폴백 PTT 와 화면 전환이 죽는다.
- 설정 판(`UiVersion` 3) — 옛 기본값 `Ctrl+Space` 를 그대로 둔 저장값은 처음 읽을 때 한 번 `Space` 로 옮긴다(직접 고른 다른 키는 그대로).

| 말한다 | 발언 바 PTT = 음성 무전(MCPTT floor) 그대로 — 영상 호에는 발언 대상 ✓ 가 없다 | D11 · TS 22.280 R-8.2.2-001~-004 |
| 무전 세션이 T4·TNG3 로 끝난다 | 영상 호는 그대로 — «채널» 은 관제사가 내 채널에 둔 의도이지 무전 세션의 수명이 아니다 | D10 · TS 24.379 §6.3.8.1 |

### 10.2 쓸 수 있는 조건 · 연결

- **사이트** — UE initial configuration 의 `MCVideo-Service-Details/Server-URI`(TS 24.484 §7.2.2.1)가 있어야 한다. 없으면(서버가 MCVideo 를 켜지 않은 사이트)
  화면에 영상 요소가 하나도 없다.
- **자격** — MCVideo user profile(TS 24.484 §9.3, `CscClient.FetchMcVideoUserProfile`)을 받으면 이용 자격이 있다(404 = 없음 → 영상 요소 없음).
- 둘 다면 PTT 계정에 `McvideoEnabled`(REGISTER Contact 의 `+g.3gpp.mcvideo`·MCVideo ICSI — TS 24.281 §7.2.1AA) · `McvideoServerUri` · `AutoAnswerMcvideo` 를 싣는다.
  계정 태그는 로그인 때 정한다 — 자격이 로그인 뒤에 생기거나 없어지면 다음 로그인에 반영된다(없어지면 영상 채널은 곧바로 나간다).
- **영상 채널** — user profile 의 `<MCVideoGroupInfo>` 목록(`McVideoUserProfileDoc.Groups`)에 있는 **멤버 그룹**. 타 채널(청취 범위 그룹)은 영상이 없다 —
  비멤버의 영상 호 합류는 403 116 이고, 권한자의 무표시 영상 보기(ambient viewing)는 V8 이다. 목록은 로그인 때와 5분 주기(CMS 문서 재조회)로 받고, **그룹 문서가 바뀌면
  (GMS xcap-diff) 그 자리에서 다시 받는다**(ETag) — 그룹에 영상을 켜거나 멤버로 편성되면 그 그룹이 곧바로 영상 채널이 되어 영상 호에 든다(주기만 기다리면 최대 5분 동안
  그 그룹의 송출 알림이 오지 않아 [보기] 가 켜지지 않는다). 같은 때 영상 채널의 **그룹 문서도 다시 받는다** — 호 방식(편성 ↔ chat)·동시 송출 상한이 바뀌었으면 로그인 중에도
  따라가고, 문서가 바뀐 채널(지문 = 문서 ETag — 같은 문서 재조회는 변경이 아니다)은 합류 물러남(실패 횟수·재시도 시각)을 지우고 MCVideo affiliation 을 다시 싣는다: 갓 만든 그룹은 서버가
  아직 MCVideo 그룹으로 모를 때 합류가 거절되거나(404 Warning 113) affiliation 이 기록되지 않을 수 있는데(PUBLISH 는 200 — 결과는 NOTIFY 로만 온다, TS 24.281 §8.2.2.2.3),
  서버는 그룹을 다시 적재한 뒤에 문서 변경을 통지한다. 영상 채널이 연결되지 않는 까닭(호 방식 편성 · 그룹 문서에 MCVideo 몫 없음 · N2·N6 한도)은 영상 절 안내와
  앱 로그(`mcvideo channel <그룹>: …`)에 남는다.
- **합류(D10)** — 영상 채널 전부를 MCVideo 로 affiliate 하고(TS 24.281 §8.2.1.2 — 관심 그룹 전부를 한 PUBLISH, 코어가 집합을 든다), chat 이면 PTT 등록 뒤
  영상 호에 합류한다(`JoinVideoGroupCall(g, {Prearranged=false, Queueing=true})` — 합류가 곧 affiliation, §9.2.2). 편성(prearranged)은 앱이 호를 열어 두지 않는다 —
  멤버가 열면 초대를 자동 수락하고(수락은 세션 합류일 뿐 영상은 [보기] 때만), 영상 호가 없으면 **[영상 보내기] 가 영상 호를 연다**(아래 «편성 영상 열기»).
  호 방식 = 그룹 문서 `mcvideo-on-network-invite-members`(어긋나면 서버가 404 117/118 — §6.3.5.2).
- **MCVideo 제휴 = 영상 채널만, 떠나면 푼다** — chat 합류는 서버가 암묵적으로 affiliate 하지만(§9.2.2.4.1.1 12)) 나갈 때 풀어 주는 절차가 규격에 없다(해제는 클라이언트 몫 —
  §8.2.1.2). 그대로 두면 옮겨 다닌 채널이 쌓여 N2 를 넘고 새 채널 합류가 486 Warning 102 로 막힌다. 그래서 영상 채널이 아니게 된 그룹(자격·user profile 에서 빠짐,
  그룹 삭제·멤버 제외로 내 채널에서 빠짐)은 영상 호를 끊고(BYE) **이어서 MCVideo 제휴도 푼다**. 여러 그룹이 한꺼번에 바뀔 때는 켜는 그룹을 먼저 싣고 끄는 그룹을 뒤에 뺀다 —
  코어 PUBLISH 는 관심 그룹 전부라 반대로 하면 빈 집합(Expires 0 = 그 사용자 MCVideo 제휴 전부 해제)을 한 번 거친다.
- **동시 제휴 그룹 한도 N2** — user profile `<MaxAffiliationsN2>`(회선 «동시 제휴 그룹», 기본 4)만큼 카드 순서대로 affiliate 한다. 넘는 채널은 영상 절에
  «동시 제휴 그룹 한도(N2 = n)가 찼습니다 — 운영자에게 한도 상향 요청» 이 서고 제휴·합류하지 않는다(넘겨 보내면 서버가 PUBLISH 에서 줄이고 chat 합류는 486 102).
- **동시 MCVideo 호 상한 N6** — user profile `<MaxSimultaneousCallsN6>` 만큼 카드 순서대로 합류한다. 넘는 채널은 영상 절에 «동시 영상 호 한도(N6 = n)가 찼습니다 —
  운영자에게 한도 상향 요청» 이 서고 합류하지 않는다(넘겨 보내면 서버가 486 103). 관제석 회선의 N6 는 영상 채널 수 이상으로 둔다(콘솔 회선 «MCVideo 이용 자격»).
- **이어 가기** — 관제사가 끝낸 것이 아닌데 영상 호가 끝나면(최대 통화 시간 TNG3·서버 해제·망) chat 채널은 다시 합류한다: 섰다가 끝난 호는 3초 뒤, 서지 못한 합류는
  10초부터 배로 최대 2분까지 물러난다(현장 앱 `PttVideo` 와 같은 규칙). 영상 채널에서 나가는 것은 그룹이 내 채널에서 빠질 때·자격이 없어질 때·로그아웃뿐이다.
  채널 상세 [나가기](무전 세션)는 영상 호를 끝내지 않는다.

### 10.3 표면

- **카드**(내 채널) — 1줄 태그 **«영상 n»**(청록 — 보고 듣는 축) = 그 영상 채널에 영상을 보내는 중인 사람 수, 없으면 태그도 없다. 보고 있으면 굵게.
  카드 조작은 늘리지 않는다(카드 = 조작 하나, §4). 툴팁 = "보내는 중 n(이름…) · 보는 중 <이름>".
- **채널 상세 «영상» 절**(영상 채널만 — 아니면 절 자체가 없다, 조작 줄 아래·로스터 위) — 머리 «영상» + 연결 상태 한 줄(«채널 참여와 함께 연결됨» · «영상 연결 중…» ·
  «편성 영상 그룹 — [영상 보내기] 로 영상 호를 엽니다» · «영상 호를 여는 중 — 멤버가 받기를 기다립니다» · N2·N6 한도 · «영상 연결 안 됨 — 사유 · n초 뒤 다시»). 상태에 따라 셋:
  ```
  ① 보내는 사람 없음      영상  채널 참여와 함께 연결됨
                          [영상 보내기](카메라가 없으면 «영상 보내기 — 카메라 없음» 비활성)
                          보내는 사람 없음 — 누가 보내면 여기에 목록이 생깁니다
  ② 누가 보냄            영상  채널 참여와 함께 연결됨
                          [영상 보내기]
                          보내는 중 2 (한 번에 1개)
                          김현장  현장지휘 · 0:34                [보기]
                          이요원  0:03                           [보기]
  ③ [보기] 뒤               ┌─ 세로 3:4 · 270×360 ─┐   ← [↻] 90° = 가로 4:3 · 360×270
                             │              [↺][↻] │
                             │  (그림 — 첫 장 전에는 │
                             │   «영상 기다리는 중…») │
                             │ 김현장 · 현장지휘 · 0:34│
                             └─────────────────────┘
                          [그만 보기] [영상 소리] [영상 보내기]
                          보내는 중 2 · 보는 중 1 (한 번에 1개)
                          김현장  현장지휘 · 0:34                보는 중
                          이요원  0:03                           [바꿔 보기]
  ```
  영상 칸은 **볼 영상이 있을 때만** 선다(고르기 전에는 영상 RTP 가 오지 않는다 — D8). 송출 줄 = 이름 · 기능 별칭 · 경과(알림을 받은 때부터) + [보기]/[바꿔 보기](요청 중 «요청 중…»)
  · «보는 중». **그림** = Windows 엔진의 창 없는 프레임 렌더(ue_sdk.md §4.5 — H.264 OpenH264 디코드 → BGRA 프레임 `Engine.VideoFrameReceived`, 영상 스레드)를
  `VideoFrames` 우편함이 보는 칸의 호만 최신 한 장씩 받아 두고(밀리면 앞 장을 덮는다 — 지연이 쌓이지 않는다) `VideoView`(WriteableBitmap `Bgr32`)가 UI 스레드에서
  그린다. 상대 해상도가 바뀌면(카메라 회전·인코더 크기) 비트맵을 새로 만든다. 첫 장 전에는 «영상 기다리는 중…»(다음 IDR 까지 — 송출 단말 IDR 주기 2 초), 영상
  미디어가 열리지 않은 호(answer port 0 — `CallInfo.Video` 거짓)는 «영상 미디어가 열리지 않았습니다 — 영상 호 소리만 들립니다». [바꿔 보기]·[그만 보기]·송출 끝은
  칸을 비워 앞 사람의 마지막 장이 남지 않게 한다.
- **영상 칸 모양·회전** — 단말 영상이 기본 **480×640 세로**(3:4)라 칸도 세로가 기본이다(오른쪽 패널 폭에 맞춰 270×360). 칸 오른쪽 위 **[↺][↻]** = 반시계·시계 방향 **90° 씩**
  돌린다 — 90°·270° 면 칸이 가로 4:3(360×270)으로 바뀌어 영상이 칸을 채운다(보내는 쪽 단말을 옆으로 들었거나 카메라가 가로로 보낼 때). 회전은 **보내는 사람마다 기억**한다
  (송출자 번호 키 — [바꿔 보기]로 돌아와도 그 사람의 방향 그대로, 앱이 켜져 있는 동안). 렌더는 영상 그림에 같은 회전(LayoutTransform)을 건다 — 자리 표시는 단말 윤곽이
  돌아 방향을 보여 준다. 보내는 쪽이 방향을 RTP 로 알리는 수단(MTSI CVO — TS 26.114 §7.4.5 `urn:3gpp:video-orientation`)은 엔진이 아직 읽지 않는다(§10.7) — 읽게 되면
  그 값이 기본이고 수동 회전은 그 위에 더한다.
- **«새 영상» 배너**(옅은 청록 면 — 착신 배너와 같은 층·모양, §3.2) — 영상 채널에 새 송출 알림(Media Transmission Notification, TS 24.581 §6.2.5.3.2)이 오면
  "새 영상 · <그룹>" / "<이름>(<기능 별칭>)이 영상을 보냅니다" · 경과 · **[보기]**(그 채널 상세를 열고 그 송출을 본다 — 보던 것이 있으면 바꿔 본다) · **[닫기]**(배너만 —
  채널 «영상 n» 목록에서 다시 [보기], TS 22.281 R-5.2.6.2.2-009 NOTE 3). 채널마다 하나(가장 최근 송출), 그 송출을 보기 시작하거나 송출이 끝나면 스스로 빠진다.
  거절·[그만 보기] 뒤 목록으로 돌아온 송출은 다시 알리지 않는다. 송출자는 아무도 보지 않으면 서버가 송출을 끝내는 시한(T11 Stream Reception Idle, 기본 10초 —
  TS 24.581 §6.3.4.4.13 #8)을 기다리고 있다.
- **«이벤트»** — 종류 [영상] 칩: "<그룹> · <이름> 영상 보내기 시작/끝" · 영상 보기 · 그만 보기 · 서버 수신 종료 · 보기 실패(«오류»).
- **[영상 보내기]**(D11 — MCVideo 송출 요청·해제, 발언 바 PTT 와 따로) — `Call.RequestTransmission`(Transmission Request, TS 24.581 §6.2.4.3.2) / 같은 자리가
  끄는 버튼이 된다: 요청 중 «요청 중… · 취소» · 대기 «대기 n번째 · 대기 취소»(Queue Position, §6.2.4.4.5) · 송출 중 «보내기 끝»(빨강) · «끝내는 중…» —
  끄기 = `ReleaseTransmission`(Transmission End Request, §6.2.4.5.3·§6.2.4.4.7·§6.2.4.9.4). 허가(§6.2.4.4.6)가 오면 코어가 카메라와 영상 호 마이크를 열고 끝나면 닫는다
  (허가 밖에서는 열지 않는다). 카메라가 없으면(엔진 영상 장치 목록에 실카메라가 없음) «영상 보내기 — 카메라 없음» 비활성. 거절 #1·#5·회수 #2·#4 = 토스트(§3.4 문구).
- **편성 영상 열기**(TS 24.281 §9.2.1.2.1.1) — 편성(prearranged) 영상 채널에 영상 호가 없으면 [영상 보내기] 가 눌리고(MCVideo 제휴가 서 있고 카메라가 있을 때), 누르면
  `JoinVideoGroupCall(g, {Prearranged=true, ImplicitTransmissionRequest=true, Queueing=true})` = 개시 INVITE 에 송출 요청을 싣는다(16) · §6.4 — TS 24.581 §14.2.4
  `mc_implicit_request`). 서버(제어 기능)는 MCVideo 로 affiliate 한 멤버를 초대하고 **첫 멤버가 붙으면 200 OK**, 10 s 안에 아무도 붙지 않으면 **480**(§9.2.1.4.2).
  그사이 다른 멤버가 먼저 열었으면 서버가 합류로 받고 암묵 요청은 받지 않는다(§14.3.5) — 코어가 명시 Transmission Request 로 잇는다. 코어는 호 성립 전에는 송출 이벤트를
  내지 않으므로 **«여는 중… · 취소»**(영상 절 «영상 호를 여는 중 — 멤버가 받기를 기다립니다»)는 앱이 그리고, 성립 뒤에는 코어 송출 이벤트를 따른다. 여는 중에 다시 누르면
  개시를 거둔다(hangup → CANCEL, 토스트 없음). **실패는 다시 열지 않는다**(chat 합류의 자동 재시도와 섞지 않는다) — 480 = «영상 호를 열지 못했습니다 — 영상을 받을 멤버가
  없습니다», 그 밖은 응답 코드·사유 토스트. 사용자가 다시 누른다.
- **내 송출 줄**(송출 중만) — 셀프뷰 160×120(내 카메라 — 코어가 송출 중일 때만 프레임을 넘긴다, 셀프뷰만으로 카메라를 열지 않는다; 거울상으로 그리고 보내는 영상은
  그대로) · «내 영상 보내는 중 · 경과 · 보는 사람 n»(보는 사람 = 서버 Media Reception Notification(§6.2.4.4.8)이 알릴 때만 센다) · D12 안내 «무전 중 — 영상은 계속,
  영상 소리는 멈춤».
- **마이크 경합 D12**(TS 22.280 R-8.3-003·-004) — 설정 [영상] «영상 보내는 중 무전»: **음성 우선**(기본 — 무전 발언(요청·대기·발언) 동안 영상 송출 호의 음성만 멈춘다,
  SDK `setMuted` 가 MCVideo 호에서는 오디오 인코더만 멈추고 영상은 계속) / **영상 우선**(영상을 보내는(요청·대기 포함) 동안 발언 바 PTT 가 무전 발언을 요청하지 않고
  한 번 알린다 — 긴급·임박 채널은 늘 말할 수 있다). 현장 앱 «영상 보내는 중 무전»(`VideoMicPolicy`)과 같은 두 값.
- **카메라** — 설정 [영상] 의 카메라 목록(엔진 영상 장치 중 실카메라 — DirectShow, 합성 색 막대·AVI 재생기 제외)에서 이름으로 고른다(빈 값 = 첫 카메라). 장치는 엔진
  기동 때 한 번 열거한다 — 새로 꽂은 카메라는 다시 로그인하면 나온다. 송출 인코딩 = H.264 640×480(가로 4:3 — PC 웹캠) 15 fps 400/500 kbit/s, IDR 2 초.

### 10.4 수신 규약 (D8 — 일반 호 manual)

- [보기] = `Call.AcceptReception(송출자 MCVideo ID)`(Receive Media Request, TS 24.581 §6.2.5.3.3) · [그만 보기] = `EndReception`(Media Reception End Request, §6.2.5.5) ·
  [바꿔 보기] = 보던 것 `EndReception` 뒤 `AcceptReception`.
- **한 번에 하나** — 1차 수신 상한 1(D8 — 한 m=video 의 여러 송출 SSRC 분리는 V8)이라 다른 송출(다른 채널 포함)을 보면 보던 것은 그만 본다. user profile
  `MaxSimultaneousVideoStreams` 가 커도 앱은 하나다(영상 벽 별창 W6 은 그 뒤 — 프레임은 이미 호별로 온다).
- 자동으로 보지 않는다 — 관제사 «새 영상 자동으로 보기»(TS 22.281 §5.2.7.1)는 W6 와 함께(사용자 결정). 긴급·방송 영상 호의 automatic 수신(§6.3.6.3.3)은 V8.
- 송출이 끝나면(Transmission End Notify → 수신 종료) 칸이 비고 남은 송출은 목록에 그대로 있다 — 다음 송출을 저절로 보지 않는다. 보던 송출이면 «<이름>이 영상 보내기를 멈췄습니다».
- **문구**(단말과 같은 사전 — 캔버스 P6): 수신 거절 #7 «더 볼 수 없습니다 — 동시에 볼 수 있는 영상(1)이 찼습니다 · [바꿔 보기]» · 서버 수신 종료 «<이름> 영상 보기가 끝났습니다»
  · 송출 끝 «<이름>이 영상 보내기를 멈췄습니다» · 송출 거절 #1·#5·회수 #2·#4(송출을 둘 때 — `ResponseText.VideoTransmissionText`). 주격 조사는 이름의 받침으로 고른다.

### 10.5 소리 (D6 · R-8.3)

- 영상 호 소리는 PTT 그룹과 같은 라우트(스피커 기본, §7).
- **같은 그룹의 영상을 보는 동안 그 그룹 무전(MCPTT 호)의 수신 음량을 줄인다**(×0.3 — 현장 앱 `VIDEO_DUCK` 과 같은 값, D6 «영상 호 송출 음성 우선»). 보기를 끝내면 되돌린다.
  다른 그룹 무전은 그대로. «소리 겹침» 정책의 설정 항목화(TS 22.280 R-8.3-003)는 사용자 결정 대기라 두지 않는다.
- **[영상 소리]** — 보는 동안 영상 호 수신 음량 막대(0~200%, 코어가 호에 기억한다 — TS 22.280 R-8.3-002 동시 오디오 원천의 상대 음량).

### 10.7 서버·엔진에 기대는 것 · 남은 것

- **영상 표시·송출의 남은 것** — 영상 칸 [창으로 ↗](영상 창 — §5 감청 창과 같은 규칙) · 다중 스트림 영상 벽(W6) · CVO 방향 읽기(TS 26.114 §7.4.5) · 카메라 핫플러그
  재열거(엔진 기동 때 한 번) · 실기(현장 앱 W999·MF52 ↔ 관제, [dispatch_windows_next.md](../../dev/dispatch_windows_next.md) §6).
- **관제석 규모** — 영상 채널마다 영상 호 하나(CMP 멤버 유닛 6 포트)를 상시 든다 · N6 를 영상 채널 수 이상으로 · 미참여 상태의 세션 가시성(conference 이벤트)은 D10 합류로
  대신했다 — [server45_handoff.md](../../dev/server45_handoff.md) §13.
- **녹취 재생** — 서버 MCVideo 녹취(같은 폴더 `recordings/ptt/{id}`, 메타 `type: mcvideo` — R3)·이력 서비스 축(R4)이 서면 [이력] PTT 세션 카드에 «영상» 칩과 영상 세그먼트 재생(§4.6).
- 송출하는 사람 쪽 «보는 사람 n» 은 서버가 Media Reception Notification 을 보낼 때만 선다(R11 — 사용자 결정 대기, 앱은 이미 센다). 긴급·방송 영상 자동 표시 · 영상
  가져오기(pull) · 원격 영상 보기(ambient viewing) · 원격 송출 요청 = V8.
- **VoLTE 감청 영상**(엔진 영상 위 후속) — 감청 창 아래 격자: 양측 영상 SSRC 2개를 2분할(caller | callee). 창은 별창이라 주 캔버스 예산은 유지. 그 전까지 감청 창은
  "영상 없음(음성 감청)" 고정 문구. 1:1 영상 통화는 «내 통화» 카드 확장(또는 별창).

- **UI 는 코어 상태의 투영**: 카드·행·패널은 `calls()`/`callInfo` 스냅샷과 구독 이벤트에서 파생하고 앱이 별도 상태 기계를 갖지 않는다(재접속·재기동 후
  화면 재구성 = 스냅샷 재조회 — 감청·청취는 인라인으로 다시 보이고 창은 다시 띄우지 않는다). 흐름(«이벤트»·«기록»)과 메시지
  모니터링은 서버 통합 이력 `GET /provisioning/history?kind=call|ptt|message`(관제 그룹 범위 게이트·커서,
  계약 [android_ue_provisioning.md §3-2](android_ue_provisioning.md))을 2~3초 커서 폴링(`nextSince`)해 채운다 —
  진행 중(live) 상태는 종전 구독(dialog/conference)이 담당한다(폴링으로 대체하지 않는다).
- 접근성: 모든 조작은 키보드 도달 가능, 상태는 색+아이콘+텍스트 삼중.

## 13. 미해결 / 향후 과제

- **앱 과제 — 타인 간 개별·애드혹 통화 세션(타 채널 «타인 세션» 줄)**: 서버 계약은 확정·구현됐다([dispatch_center.md §5.6a](dispatch_center.md)) —
  `dispatch.members[].pttId` 에 `Event: dialog` 구독(VoLTE `volteAor` 와 같은 `dialogWatch`) → PTT 세션 참가 leg 마다 dialog(remote = 세션 URI
  `sip:priv-…|adhoc-…|g002@<ptt 도메인>`, 확장 `<mcptt session-type initiator emergency imminent-peril/>`). 앱: 같은 remote 의 dialog 를 한 카드로
  묶고(참가자 = 감시 회선 중 그 세션에 있는 사람), `session-type` 이 `private|adhoc` 이면 타인 세션 줄, 그 외는 내 채널 카드·타 채널 행의 참가 정보로 흡수.
  [청취] = 세션 URI 로 `joinGroupCall(listenOnly)`, 참가자 전부가 필요하면 세션 URI conference 구독 — 둘 다 서버의 즉석 세션 관측 인가(참가자
  `monitor_scope`)를 받아 403 이면 `Area.PttListen` 문구. `members[]` 에 `volteAor=""` 인 PTT 전용 가입자가 올 수 있다(`monitorScope=all`) — 앱은 이들을 VoLTE dialog
  감시·«관제 그룹원» 칸에서 뺀다(`DirectoryService.SetMembers`, extension 은 표시 라벨이라 주소로 쓰지 않음). PTT dialog 구독이 SDK 에 생기면 `pttId` 로 붙인다.
  SDK: `dialogWatch` 가 PTT 계정으로도 구독하고 `<mcptt>` 확장을 이벤트 필드로 노출해야 한다.
- **발언 세트 저장**(`talksets.json` — 저장된 ✓ 조합, §8 `Ctrl+Shift+F1..F4`)은 앱 로컬 설정으로 둔다(미구현).
- **주소록 소스 = 서버 회사 전화번호부** `GET /provisioning/directory?service=volte|ptt`([android_ue_provisioning.md](android_ue_provisioning.md) §3-1 — 조직 트리 +
  가입자, ETag/304, Android 연락처 탭과 같은 소스·동선: 조직 범위 선택 + 조직별 섹션 + 검색 + 홈 국가 로컬 표기). 앱은 `directory-cache.json` 에 캐시한다.
  서버·CSV 병합과 이름 조회의 키는 **E.164 정규형**(홈 국가의 `010…` 은 `+8210…` 으로, 6자리 이하 내선은 그대로)이라 표기가 달라도 한 연락처다.
  **관제 그룹원·청취 대상은 서버가 준다**: `dispatch` 블록 `members[]`(항목 `groupId` 로 자기 그룹원 = «관제 그룹원» 칸 / 그 외 = 감시 전용)·
  `pttTargets[]`·`etag` + 응답 `ETag`/`If-None-Match` 304([android_ue_provisioning.md §3](android_ue_provisioning.md)). 앱은 두 배열을
  dialog watch·conference 구독 대상으로 쓰고(로컬 CSV `member` 태그 폴백은 구 서버용), 주기 재조회로 편성 변경을 따라간다. 외부망 연락처(CSV `external`).
- **PTT 그룹 생성·편집·삭제를 관제 앱에서** — 경로는 **GMS XCAP**(TS 24.481, 생성 주체 = 권한 있는 가입자 = 관제사, PKCE 토큰)로 확정.
  관리 API `/api/v1/ptt/groups`([admin_api.md](../../api/admin_api.md) §6)는 콘솔 토큰 전용으로 그대로 둔다. 자격 = `ptt_user_profile.allow_group_creation`
  (프로비저닝 `ptt.allowCreateGroup`), 편집·삭제 = 본인 소유(`authorized_user_id`) 그룹만 — 서버 구현 요청은 위 요청서 §1.
  앱: [PTT 그룹] 화면 인라인 폼(`GroupEditView` — [사용자] 패널 [그룹으로 저장 ›]·채널 상세 ⋮ [편집]도 같은 폼, §4.7)·[삭제] → `CscClient.PutGroup/DeleteGroup` → `RefreshGroupsAsync`
  (GMS 목록 재조회 + 신규 그룹 affiliation·conference 구독, 삭제 그룹 해제).
- **조직·구성원·번호·전화 그룹 관리 = 관리 화면(§4.5)** — 역할 `directory_write` 범위 안에서 앱이 직접 편집하고(`/provisioning/directory/*`), 역할
  편성(감청/청취/관리 범위·배정)은 콘솔 `관리 > 역할` 몫이다(앱에서는 어떤 경로로도 만들 수 없다). 남은 것: 조직 트리 드래그 이동, 구성원 일괄 가져오기 화면(서버 `POST /provisioning/directory/members/import` —
  CSV/JSON 행 단위 결과, [android_ue_provisioning.md §3-3](android_ue_provisioning.md) — 관리 화면 서브내비의 "예정" 자리에 파일 선택 + 결과 표), 회선 여러 개인 구성원(앱은 종류당 첫 번호만 관리).
- **별창 화면의 위치 기억** — 화면 별창(§3.4)은 아직 위치·크기를 기억하지 않는다(감청 창처럼 `layout.json` 에 기억할 것).
- **청취 범위 그룹의 conference 이벤트 구독**은 서버가 인가한다([dispatch_center.md §5.6](dispatch_center.md), TS 24.379 §10.1.3.4.1) — `pttTargets[]`
  그룹 구독은 200(타 채널 행의 "진행/참가자 수" 소스), 범위 밖·자격 없음은 **403 + `Warning: 138`**(앱은 `Area.PttListen` 403 문구로 흡수, 재시도
  루프 금지), 브로드캐스트 그룹은 480 + Warning 105.
- **녹취 재생 후속**: 파형(`/peaks`)·단독 발언자 트랙(`slot`) 선택·VoLTE 두 화자 분리 재생·영상 세그먼트(F3) — 서버는 이미 내며 앱 UI 만 남았다.
  OAM 녹취·이력 API 는 콘솔 admin JWT(role ≥ monitor, 삭제 manager) 게이트를 받고 CSC 프록시는 공유 시크릿 서비스 토큰으로 부른다 — 앱은 CSC 경로만 쓴다.
- **서버 통합 이력 조회(메시지 모니터링 포함) — 앱 `Services/HistoryClient`**: 관제 범위 안에서 **끝난** 통화·PTT 세션·메시지를 수초 지연으로 «이벤트»·«기록» 에
  합친다. 진행 중 상태는 dialog/conference 구독이 정본이라 폴링이 live 를 대체하지 않는다. 메시지 모니터링은 **실시간 사본 없이 이력 조회만**으로 결정
  ([mcdata_messaging.md §4.3](mcdata_messaging.md)).
  - 요청: `GET /provisioning/history?kind=call|ptt|message&since=<cursor>&limit=200`(CSC 4430, PKCE Bearer, `If-None-Match` → 304). kind 별로 커서·ETag 독립,
    2.5 초 주기. 로그인 직후 `kind=call&limit=1` 탐침 — 404/501 이면 서버 미구현으로 조용히 꺼지고, 403 이면 범위 밖으로 꺼진다(재시도 없음).
    CSC 에 닿지 않으면(재배포·망 단절) 주기를 지수 백오프(최대 30 초)로 늘리고 경고는 단절·복구 시 한 번씩만 남긴다 — 복구되면 커서 그대로 이어 받는다.
  - 응답(앱이 읽는 것 — 서버 계약 [android_ue_provisioning.md §3-2](android_ue_provisioning.md), 필드 추가는 무시): `{ "items": [ { "id", "time"(ISO 8601+offset),
    "kind", "event", "from", "to", "group"(URI), "duration"(초), "emergency", "text" } ], "next": "<다음 커서>", "hours": {…} }` + 응답 헤더 `ETag`(If-None-Match→304).
    `id` 가 중복 제거 키, `items` 는 `time` 오름차순. 종류별 확장 필드(§3-2 — 상태·시각·종료사유·PTT 지표)는 파서가 읽어 두지만 «이벤트»·«기록» 병합은 쓰지 않는다(이력 화면 §4.6 전용). `event` = call.answered/missed·ptt.session.start/end·message.sds/sms — 앱이 이름표로
    «이벤트»(ptt·그룹 sds)·«기록»(call·1:1 sms — 상대별 줄의 한 줄기) 에 매핑한다(상세 문구 = 길이 또는 이름표 한글). 내가 당사자인 항목과 **대표번호 호**(로컬 dialog 가 정본, §4.3)는
    건너뛰고, 넣는 행은 `IsOthers` 로 표시해 데스크 응대·부재 집계에서 뺀다.
  - 내가 당사자(`from`/`to` 가 내 PTT·VoLTE 번호)인 항목은 로컬 행이 이미 있어 건너뛴다. 이름은 주소록으로, 그룹은 GMS 목록 이름으로 표시.
- **서버 과제 — 외부망 SMS/LMS 게이트웨이**: 현재 MESSAGE 는 등록 가입자 간 전달만. 외부망 휴대전화 문자는 IBCF→SMSC(TS 24.341 SMS over IMS) 또는 SMPP
  게이트웨이가 필요하다. 앱은 능력 키(프로비저닝 `services[kind].capabilities.smsGateway` — csc.json `Provisioning.Services.<kind>.sms_gateway`, 기본 `false`)로
  외부 번호 [문자] 를 켜고 끈다(§4.4).
- **U10 관측 API** — `MediaSource.level/active` 실시간 갱신 확정 후 감청 창 레벨 미터 활성.
- **자동 수락 분리** — `AccountConfig.autoAnswerMcptt` 는 그룹콜·개별 통화 공통. 관제석은 그룹콜 자동 + 개별 통화 수동이 맞아 코어 플래그 분리 필요
  (규격은 수락 방식을 호 종류별로 둔다 — TS 24.379 §6.2.3 commencement mode, 개별 통화·그룹콜 각각 자동/수동, [ue_sdk.md §11](ue_sdk.md)).
  **긴급 개별 통화의 전역 표시**도 이것과 함께 정한다 — 긴급 배너는 개별 통화를 빼고(`UpdateEmergencyBanner`, 착신 배너의 몫) 착신 배너는 자동 수락으로
  잠깐만 서며 긴급 여부도 적지 않아, 다른 화면에 있는 동안 받은 긴급 개별 통화는 내 채널 카드 빨강(과 [관제]·[무전] 배지)이 유일한 표시다.
- **진행 중 조건의 개시자** — 조건 재광고 re-INVITE 는 조건을 건 사용자를 싣지만(TS 24.379 §6.3.3.1.6 2)) 코어 `McpttCondition` 에 개시자가 없어
  진행 중에 걸린 조건의 배너 개시자는 비어 있다(§3.2, [ue_sdk.md §11](ue_sdk.md)).
- **대표번호 발신 표시** — 서버 확정([dispatch_center.md §4.7](dispatch_center.md)): 발신 INVITE 에 `P-Preferred-Identity: <sip:<pilotId>@…>` 를 실으면
  CSP 가 자기 관제 그룹 대표번호일 때 착신자에게 대표번호로 낸다(그 외는 무시 → 기본 신원). 앱: «통화» 머리 번호칸 옆 "대표번호로 발신" 토글(`dispatch.pilotId`
  있을 때) + SDK `makeCall` 헤더 옵션(남음).
- **MCVideo 영상** — 그림·[영상 보내기]·셀프뷰·D12 는 된다(§10.3). 남은 것 = [창으로 ↗] 영상 창 · 다중 스트림 영상 벽(W6) · CVO · 실기(§10.7). Android 태블릿 짝은 Windows 안정화 뒤.

  영상 녹취·이력 서비스 축.

## 14. 실기 시험 환경 — 개발 서버(.45) 등록 계획

앱 실기 시험(§2 표의 작업 전부)을 위해 `.45` 개발 서버(`121.161.164.45` — CSC·CSP·CMP 동거)에 아래를 등록한다. 서버 쪽 등록이 끝나면
앱은 로그인 창에 CSC 주소·관제석 계정만 넣어 붙는다. 스키마 전제 = `sql/migrate_dispatch_groups.sql` ·
`sql/migrate_ptt_ambient_listening.sql` 적용([dispatch_center.md](dispatch_center.md) §8.1), CSC 관리 API 는 [admin_api.md](../../api/admin_api.md) §6.7.
콘솔에서는 `구성 > 사용자`(가입자·번호)·`구성 > 전화 그룹`(대표번호·호출 방식·멤버)·`관리 > 역할`(감청/청취/관리 범위·배정) 화면이 같은 API 를 쓴다(현 콘솔 = `구성 > 관제 그룹` 한 화면).

**번호 체계** — 망 신원은 가입자당 글로벌 E.164 하나다(관제석 `+82131000100x`, 대표번호 `+821310001000` — 대표번호는 TS 24.239
Flexible Alerting pilot 로 가상·미등록·포크). **내선 4자리는 망 주소가 아니라 관제 앱 주소록의 표시 라벨**이다(아래 directory.csv —
서버·콘솔에 내선 엔티티는 없다). 일반번호와 내선을 둘 다 망 주소로 두는 것(TS 23.228 implicit registration set / 별칭)은
[volte_supplementary_services.md](volte_supplementary_services.md) §9 향후 과제라, 시험은 이 규약으로 간다.

### 14.2 앱이 서버에서 기대하는 것

- `POST /oauth/token`(PKCE) 로그인 → `GET /provisioning/me` 응답에 `services[volte, ptt]`(각 `sipHost/sipPort/transport/domain/msisdn/imsi/authId/sipHa1`,
  PTT 는 `mcpttId`) + **`dispatch` 블록** `{present:true, groupId:"dg-dispatch01", groupName:"관제1", pilotId:"+821310001000", monitorScope:"none"|"all",
  pttListen:"none"|"all", listenVisibility:"hidden"}`. `present=false` 면 앱은 소프트폰 모드(§6).
- GMS `listGroups(<PTT 번호 tel: URI>)` 가 `g002` 를 돌려준다(카드 소스). 대표번호 `+821310001000` 과 그룹원 번호는 앱이 `dialogWatch` 로 구독하므로
  CSP 의 dialog 이벤트 인가(`monitor_scope`)가 두 관제석 모두에 적용돼야 한다.
- 그룹원 목록은 프로비저닝 `dispatch.members[]`(§13, csc 0.2.104)가 정본이고 앱 로컬 `%APPDATA%\CIMS\dispatch-desktop\directory.csv` 는 구 서버 폴백·외부망 연락처용이다. `number` 는 실제로 다이얼되는
  망 주소(E.164)이고 내선 4자리는 `name` 에 병기하는 표시 라벨이다(단축 다이얼 열은 §13 후속) — 시험용 내용:
  ```
  kind,number,name,tags
  ext,+821310001001,관제1석 1001,member
  ext,+821310001002,관제2석 1002,member
  ext,+821300000001,시험단말A,
  ext,+821300000002,시험단말B,
  external,02-120,교통상황실,
  ptt,+82500000001,PTT단말1,
  ptt,+82500000002,PTT단말2,
  ```

### 14.3 시험 순서(일괄)

1. 두 관제석 로그인·등록(PTT·VoLTE 점등 녹색) → 내 채널 카드 `g002` ✓·발언 바 PTT 발언·채널 상세 로스터 → «메시지» MCData 그룹 SDS 왕복(✓✓).
2. 시험단말 → `+821310001000` 발신 → 두 관제석 착신 배너(주황)·«통화» 대기열 → 한쪽 응답, 다른 쪽 [당겨받기]/무응답 부재(«기록» [부재]).
3. 시험단말A ↔ B 통화 → «진행 중» 행 [청취] → 행 확장(caller/callee 두 줄) · [창으로 ↗] 감청 창 → 종료 시 행이 사라지고 창은 자동 닫힘. «관제 그룹원» 칸에서 상대 관제석 통화 [청취].
4. 관제석 ① 착신 링 중 ②가 [픽업](지정)·`**`(그룹) → 픽업 행. 통화 중 [전달▾] blind / [상담 전달] attended.
5. 청취 범위 그룹(예: `g003`) 세션(PTT 단말 2대) → 타 채널 행 [청취] 토글(발언자·참가자) · 채널 상세 [창으로 ↗] → PTT 청취 창. 개별 통화(반이중·전이중)·애드혹 그룹([사용자] 패널 고르기) 카드.
6. SMS·LMS(`+821310001001`↔`+821310001002`, 70자 초과 — «기록» 상대 줄 입력) · 출력 [헤드셋]/[스피커] · 핫키(Space PTT — 입력칸 밖, F9 응답, F8 픽업, F10 종료) · 칸 경계 끌기·창 위치 저장/복원.
